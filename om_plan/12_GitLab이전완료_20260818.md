## 검사기 clean export — 사용자 결정으로 계획 변경

원계획(작업장 통째 이전 → 운영 반입 때 clean)과 달리, 사용자가 **"깃랩에는 완성본만,
전체본은 깃허브에 있으니 충분"**을 결정 → 이전 시점에 clean export 수행.

**포함 (파이프라인 import 폐쇄집합을 기계 계산으로 도출):**
`.gitlab-ci.yml` · `harness/ci/` · `om_workflow.py` · `pyproject.toml` ·
`acgh/{verdict,gitprim,binding}.py` · `acgh/plancore/` · `acgh/integrations/om/` ·
`registrations/om-temp-1.13.1/` · `tests/bank/contracts/` · plan·기반 반례 테스트 ·
`.github/workflows/`(참조 보존 — 이를 검사하는 테스트 3종 때문에도 필요)

**제외:** 구식 검사 모듈 45개+그 테스트 · 과거 등록자료(om-temp-1.13.0·kb-openmetadata) ·
구식 스크립트 12종 · harness/policies(신 엔진 미참조, 활성 등록자료가 자체 정책 보유) ·
docs·evidence·deliverables·핸드오프 — 전부 작업장 GitHub에 보존.

**검증:** 클린 구성 단독으로 반례 테스트 131개 통과(2 skip은 타 환경 전용 미러 경로 —
환경 사유). CI가 docs·evidence·deliverables를 참조하지 않음을 grep으로 확인.

## 이전 중 사건 기록

- 1차 push가 작업장 통짜(50MB)로 나감 → 사용자 지적으로 clean 결정 → force push 교체
  (GitLab 보호가 1차 차단, 사용자가 토글 임시 허용)
- 검사기 로컬 사본이 shallow라 push 거부 → GitHub에서 완전 클론 후 해결
- 클린 v1(harness 통째)도 불충분 판정(사용자 지적: 구식 기능·예행연습 잔재) → import
  폐쇄집합 기반 v2로 재구성
- Claude 실수 1건: 테스트 결과 확인 전에 push를 체인으로 이어붙임(보호 설정이 차단해
  무사고) → 이후 단계별 결과 확인 후 진행으로 교정
