### ID 패턴 결정

활성 등록자료의 실물 ID는 `BANK-OM-001`부터 `BANK-OM-007`이다. 기존 제품 정책은
`harness/acgh/integrations/om/config.py:7`의
`^BANK-OM-[0-9]{3,}$`이며, 이미 3자리 이상 확장을 허용한다.

공통 엔진인 `plancore`에 `BANK-OM`을 직접 넣으면 기존 경계 검사에서
`forbidden token BANK-OM`으로 실패한다. 따라서 다음 2계층으로 적용했다.

1. 공통 JSON Schema: `^[A-Za-z0-9][A-Za-z0-9._-]*$`
2. OpenMetadata 어댑터: 기존 `^BANK-OM-[0-9]{3,}$`

이 구성은 feature 필수 입력과 형식 검사를 모두 수행하면서 제품 독립적인
`plancore` 경계를 보존한다. `BANK-OM-12`, `OTHER-001` 반례도 어댑터에서
`CUSTOMIZATION_ID_INVALID`로 거부되는 것을 테스트했다.

### 반례 실행 출력

#### 1. feature 요청에서 ID 생략

```json
{
  "status": "analysis_error",
  "code": "SCHEMA_INVALID",
  "details": {
    "issues": [
      {
        "field": "<root>",
        "message": "'customization_id' is a required property"
      }
    ]
  }
}
```

스키마 우회 직접 호출은 `None`과 빈 문자열 모두
`CUSTOMIZATION_ID_REQUIRED`로 거부한다.

#### 2. 기존 ID를 신규 feature 요청 ID로 사용

```json
{
  "verdict": "block",
  "reasons": [
    "feature customization id already exists in the registry",
    "feature proposal reuses registered customization ids: ['BANK-OM-001']"
  ]
}
```

#### 3. 제안서의 affected ID 바꿔치기 또는 기존 ID 혼입

요청 ID `BANK-OM-003`, 제안 ID `BANK-OM-004`:

```json
{
  "verdict": "block",
  "reasons": [
    "feature proposal affected customization ids must equal the requested id: expected ['BANK-OM-003'], got ['BANK-OM-004']"
  ]
}
```

요청 ID `BANK-OM-003`, 제안 ID에 기존 `BANK-OM-001` 혼입:

```json
{
  "verdict": "block",
  "reasons": [
    "feature proposal affected customization ids must equal the requested id: expected ['BANK-OM-003'], got ['BANK-OM-001', 'BANK-OM-003']",
    "feature proposal reuses registered customization ids: ['BANK-OM-001']"
  ]
}
```

## P0-2 — Python 3.11+ 표준 실행기와 Hook 정합

### 실행기 계약

신규 실행기: `harness/om` (실행 권한 포함)

```text
harness/om <om_workflow.py에 전달할 인수 그대로>
```

선택 순서는 다음과 같다.

1. 저장소 내부 `.venv/bin/python`
2. PATH의 명시적 버전 실행기 `python3.14` → `python3.11`
3. 없거나 버전 미달이면 종료코드 2

일반 이름 `python`·`python3`은 선택하지 않는다. 저장소 `.venv`가 있는데 3.11
미만이면 다른 PATH Python으로 몰래 우회하지 않고 오류로 중단한다.

현재 저장소에서 지원 Python을 의도적으로 PATH에서 제거한 실측 출력:

```text
runner_exit=2
Python 3.11+ 필요: 저장소에 .venv를 만들거나 python3.11 이상을 설치하세요.
```

우선순위·인수 보존·일반 `python3` 미사용·명시 실패 반례는
`harness/tests/test_om_runner.py:41-116`에 있다.

### Hook·권한 정합

- `harness/acgh/plancore/hook_policy.py:51-121`
  - `harness/om plan …`과 기존 직접 Python 호출을 같은 신뢰 명령으로 해석한다.
  - 단순 문자열 포함을 신뢰하지 않고 실제 첫 실행 명령만 해석한다.
  - 쉘 연산자, `verify`·`apply`, `echo harness/om …` 위장은 허용하지 않는다.
- `.claude/settings.json:46-56`
  - 기존 직접 Python bootstrap 차단에 `harness/om bootstrap` 차단을 추가했다.
  - 실행 중 run·명령별 허용 여부는 정적 allow로 넓히지 않고 PreToolUse Hook이
    marker 상태를 보고 결정한다.
- `README.md:5-21`, `CLAUDE.md:3-7`
  - 사람과 Claude의 표준 명령을 `harness/om`으로 통일했다.

실측 Hook 판정:

```json
[
  {"command":"harness/om plan start request.yaml","allowed":true},
  {"command":"python harness/om_workflow.py plan start request.yaml","allowed":true},
  {"command":"harness/om verify run request.yaml --run-dir run","allowed":false},
  {"command":"echo harness/om plan start request.yaml","allowed":false},
  {"command":"harness/om plan start request.yaml && git push origin main","allowed":false}
]
```

즉, 새 래퍼 경로를 허용하면서 기존 직접 Python 경로는 하위 호환되고, 래퍼
이름을 문자열에 끼워 넣는 우회는 차단된다.
