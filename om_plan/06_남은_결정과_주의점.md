## 구현 후 확인된 주의점

- GitHub release HTML은 동적 byte가 포함될 수 있어 서로 다른 run의 문서 digest가 달라질 수 있다. 같은 run 안의 무결성 검증은 보장하지만, 별도 run 간 의미 동일성까지 보장한다는 뜻은 아니다.
- 예행연습 원본은 `/private/tmp`에 있어 영구 증거가 아니다. 새 컴퓨터에서는 테스트를 다시 실행하거나 영구 evidence 정책을 먼저 정해야 한다.
- `approval`은 계획을 사람이 검토할 준비가 됐다는 뜻이다. 제품 코드 반영·배포·운영 승인이 아니다.
- Skill·Hook 운영 설치, clean export, CI wrapper, `/om-implement`, `/om-verify`는 아직 범위 밖이다.
- 다음 작업은 `07`의 순서를 따른다.
