## 2. 구현된 범위

- `plan-session-start`, `plan-preflight`, `plan-validate`, `plan-resume` CLI
- `initial`, `feature`, `change`, `upgrade` 모드
- change의 `pre_plan`, `post_change_reconcile` 두 경로
- 인접 버전만 허용하는 upgrade, owner 미정 STOP, 배포 방식 매 run 입력
- 제품 무관 `acgh/plancore`와 OpenMetadata 전용 `acgh/integrations/om` 분리
- run request·input lock·discovered facts·validation attempt·plan result Schema
- canonical 입력과 관찰 결과 분리, 사실 재수집 대조, 3-digest plan binding
- session/run 2계층 marker와 기본 차단 Hook
- 공식 업그레이드 문서 raw byte snapshot·digest·version token
- 완료된 run 재사용 금지, 제안 검증 실패만 같은 run에서 proposal 수정 후 재검증

아직 구현하지 않은 범위는 운영 Skill 설치, 제품 코드 반영, runtime contract,
배포 이미지 검증, merge·release, `/om-implement`, `/om-verify`다.

## 5. 구현 중 발견해 고친 문제

1. YAML의 `1.13`이 숫자로 해석되는 문제를 Schema 오류로 드러내고 입력을 문자열로 고정했다.

3. 재시도 사이 checker 변경은 `analysis_error`로 차단한다.

- 구현 commit/tree가 위 기준과 다르면 먼저 변경 이유를 확인한다.
- 제품 코드나 활성 등록자료를 수정해야 하면 작업을 멈추고 별도 승인을 받는다.

- 네트워크 때문에 공식 ref·문서·blob을 검증하지 못하면 통과로 바꾸지 말고 `analysis_error`로 보고한다.
