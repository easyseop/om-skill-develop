# 관리 파일 × 모드 전수 검토 (2026-08-20)

질문: initial이 베이스(전체 건설)라면, feature·change·upgrade에서 **각 관리 파일이 정말 업데이트 안 돼도 되는가**를 파일 하나하나 검토.

## 확정 사실 (코드)

- **apply 쓰기 화이트리스트**(`registration_prep.py:966-971`): apply는 아래 4종만 쓴다.
  1. `commit-inventory.yaml` 2. `current-diff-paths.txt` 3. `customization-registry.yaml`(신규 entry append; 기존 entry·`source` 블록은 deepcopy로 보존=미변경) 4. `manifests/BANK-OM-*.yaml`(변경분).
- **나머지는 apply가 절대 안 씀**: `contracts.yaml`, `shared-code-definitions.yaml`, `shared-path-owners.yaml`, `source-snapshot-path-owners.yaml`, `sensitive-zones.yaml`, `repository-layout.yaml`, `source-diff-paths.txt`. → 이들은 **bootstrap(initial) 또는 사람만** 갱신.

## 전수 매트릭스

범례: ✅=현재도 갱신됨/올바르게 미갱신 · ⚠️=갱신돼야 하는데 안 됨(갭) · —=해당 없음

## 갭이 두 덩어리로 모임

### 덩어리 A — feature/change 델타가 "공유/계약 base 파일"에 전파 안 됨
- `contracts.yaml`, `shared-path-owners.yaml`, `shared-code-definitions.yaml`, registry entry의 `contracts` 리스트.
- 문제: 새 기능이 계약·공유경로를 만들거나, 변경이 공유경로를 도입해도 **apply 화이트리스트가 이 파일들을 못 써서** base가 낡은 채로 남는다.
- 성격: 이 파일들은 **사람 큐레이션**(계약=지켜야 할 동작, 공유경로 소유자=사람 확정)일 수 있어 apply가 자동으로 안 쓰는 게 부분적으로 의도. **하지만 그럼 계획이 "사람아, contracts.yaml에 CONTRACT-X 추가하라"를 강제·명시해야** 한다 — 현재 feature는 질문으로 flag만, 강제 아님(= Q11류 미강제).

### 덩어리 B — upgrade가 "원본(source) 스코프 파일"을 재베이스 안 함
- `source` 블록(`upstream_sha/tag`), `source-snapshot-path-owners.yaml`, `source-diff-paths.txt`, `sensitive-zones.upstream_base_sha`, `repository-layout.upstream_base_sha`.
- 문제: 공식 버전이 바뀌었는데 apply가 원본 기준을 새 버전으로 갱신 안 함 → **이게 큰 Q10(upgrade 반영 경로)**. 새 버전 등록을 apply가 만드나, 새 bootstrap이 만드나 미규정.

## 올바르게 "미갱신"인 것 (갭 아님)

- feature/change의 `source` 블록·`source-snapshot-path-owners`·`source-diff-paths.txt`: 원본 스냅샷은 불변이 정상(P1-1 원본 기준 결정과 정합). 델타는 그 위에 얹힘.
- feature/change의 정책 파일(`sensitive-zones`, `repository-layout`): 정책은 사람이 바꿈, 모드가 자동으로 안 바꾸는 게 정상.

## 결론 / 결정거리

- **덩어리 A**: feature/change가 계약·공유경로·공유코드·registry contracts를 **바꿔야 할 때 base에 반영·강제되는가**가 갭. 두 갈래:
  - (A) 계획이 이들 갱신을 **필수 산출물로 강제**(upgrade 9항목처럼) + 사람 큐레이션 파일은 "사람 작업"으로 명시 강제. → 새 결정 Q12.
  - (B) 현행(질문/flag) 유지 + 사람·2차판독 의존.
- **덩어리 B**: = Q10(별도, 열림).
- 정직 고지: 이 검토는 apply 화이트리스트·매니페스트 로직 코드 대조 기반. "필요?" 판정 중 사람-큐레이션 파일(계약·공유경로 소유자)의 자동/수동 경계는 설계 의도 확인이 더 필요(추정 포함).
