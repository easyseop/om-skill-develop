# Codex 핫픽스 지시 — 새 공유 경로의 사람 승인 창구 (엔진 설계 공백)

작성일: 2026-08-28. **실기동 확정 공백**: apply check가 approval(사유 0)인데 새 공유 경로 4건 질문 때문에 `final_state: awaiting_shared_path_review`·`eligible: false`로 고정 — 엔진에 사람 승인을 전달할 방법이 없어(옵션은 --final-ref뿐, execution-report 스키마에 승인 필드 없음, verifycore/workflow.py:118은 삼중 조건 요구) **새 공유가 생기는 업그레이드는 구조적으로 /om-verify 도달 불가**. 업그레이드의 정상 시나리오(파일 분해·이관)가 항상 새 공유를 만들므로 P0.

대상: clean-export 작업트리(main 기준). **커밋·push·MR 금지**(Claude 검증 후 대행).

## 요구사항

1. **승인 창구**: `execution-report.yaml` 스키마에 `shared_path_acknowledgments` 배열 추가 — 항목 {path, customization_ids(정확한 조합), approved_by, rationale}. apply check는 baseline_shared에 없는 새 공유 경로 각각에 대해: 일치하는 승인 항목(경로+ID 조합 정확 일치)이 있으면 질문 해소, 전부 해소되고 다른 사유 없으면 `static_consistent_awaiting_verify`·`eligible: true`.
2. **완화 금지**: 승인 없는 새 공유는 기존대로 awaiting 유지. 승인 항목의 ID 조합이 실측과 다르면 수용 금지(명시 사유로 지적). 실제 새 공유가 아닌 경로에 대한 승인 항목은 무시가 아니라 경고(잉여 승인 지적).
3. **재검사 지원**: 완료된 apply run 디렉터리에 승인 필드를 추가한 뒤 `apply check --final-ref <동일 SHA>`를 재실행하면 final_state가 재산정되어야 함(전체 재주행 없이 이번 run 구제). 불가하면 그 사실과 대안(최소 재주행 경로)을 결과서에 명시.
4. **반례 테스트**: ① 승인 없음→awaiting 유지 ② ID 조합 불일치→수용 거부 ③ 정확 일치→awaiting_verify 도달·eligible true ④ 잉여 승인→경고 ⑤ 기존 반례·전체 테스트 green.
