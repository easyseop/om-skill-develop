## 반드시 확인할 것

1. `plancore`가 BANK-OM·OpenMetadata 경로·om-temp 상수를 알지 않고 OM 통합 계층이 주입하는가.
2. input-lock과 discovered-facts를 validate가 다시 계산해 바꿔치기를 차단하는가.
3. marker Hook을 끄거나 우회해도 validate가 최후 안전망으로 실패하는가.
4. session/run marker가 병행 세션과 실패 cleanup에서 서로의 보호를 해제하지 않는가.
5. change의 `pre_plan`과 `post_change_reconcile`가 서로 다른 입력·검증을 실제로 수행하는가.
6. 완료된 run 재사용은 막고, proposal 검증 실패만 사실 자료 불변 조건으로 같은 run 재시도가 가능한가.
7. upgrade가 인접 버전·세 commit·공식 문서 raw bytes와 version token을 검증하는가.
8. observed/proposed 구분을 LLM이 파일 편집만으로 승격할 수 없는가.
9. Q3·Q6·Q7·Q8·Q9가 코드에서 몰래 확정되지 않았는가.
10. C01~C43·R01~R07이 단순 이름만 존재하는 것이 아니라 해당 결함을 넣은 mutant에서 실제 실패하는가.
11. 실제 1.13.1 initial/change와 1.13.2 upgrade 경로가 synthetic test만으로는 드러나지 않는 오류를 숨기지 않는가.
12. test 개수·green 여부가 아니라 false pass와 우회 가능성을 기준으로 결론을 냈는가.
