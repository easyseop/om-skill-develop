## 1. 목적과 적용 결정

등록자료의 `source.changed_path_count`는 현재 custom branch의 변경 경로 수가 아니라, 등록 당시 원본 스냅샷의 `source-diff-paths.txt` 경로 수를 의미한다.

따라서 다음 A5 변경은 잘못된 스코프를 비교하므로 되돌렸다.

- apply가 `current-diff-paths.txt` 행수로 `source.changed_path_count`를 다시 쓰는 동작
- 등록자료 validator가 `current-diff-paths.txt` 행수와 `source.changed_path_count`를 비교하는 동작
- 위 두 동작을 정상으로 간주하던 테스트

결정 근거:

- `skill_develop/om_plan/24_누락감사_사람결정과_기록_20260820.md`의 P1-1 확정 결정
- `skill_develop/om_plan/23_Codex_갭조치_지시서_20260820.md`의 조치 4 본문

주의: `23` 문서의 마지막 수용 기준 표 4번에는 이전의 current-diff 기준 문구가 남아 있다. 이 문구는 같은 문서의 갱신된 조치 4 본문 및 `24`의 확정 결정과 반대이므로 적용하지 않았다.

## 2. 수행 결과

### 2.1 `registration_prep.py`

제거한 동작:

```python
registry_after["source"]["changed_path_count"] = len(current_diff_paths)
```

현재 `apply_plan`은 `current-diff-paths.txt`를 정보 파일로 갱신하지만, 그 행수로 `customization-registry.yaml`의 원본 경로 수를 바꾸지 않는다.

확인 위치:

- `work/review-openmetadata-test-om-plan/harness/acgh/registration_prep.py:1054-1068`

이 변경은 미커밋 A5 추가분을 기준 commit 상태로 복원한 것이므로, 최종 `git diff`에는 코드 삭제가 남지 않는다.

### 2.2 `validate_registration_bundle.py`

제거한 동작:

- `validate_current_diff_count` 함수
- `main()`에서 해당 함수를 호출하던 코드

현재 validator는 `current-diff-paths.txt`와 원본 count를 비교하지 않는다. 대신 아래의 기존 reconstruction plan 검사가 `source-diff-paths.txt`에서 읽은 inventory 수를 원본 count와 비교한다.

확인 위치:

- validator 호출 흐름: `work/review-openmetadata-test-om-plan/harness/registrations/om-temp-1.13.0/validate_registration_bundle.py:55-76`
- 원본 불변식: `work/review-openmetadata-test-om-plan/harness/acgh/vendor_rebuild.py:87-106`

### 2.3 기존의 잘못된 테스트

다음 테스트를 제거했다.

- `test_apply_recalculates_changed_path_count_from_current_diff`
- `test_current_diff_count_mismatch_is_rejected`

두 테스트에만 필요했던 `pytest`·`SimpleNamespace` import도 `test_registration_validation_workflow.py`에서 제거했다.

이 삭제 역시 미커밋 A5 추가분을 기준 commit 상태로 복원한 것이므로 최종 diff에는 남지 않는다.

### 2.4 추가한 반례 테스트

같은 잘못이 다시 들어오는 것을 막기 위해 두 반례를 추가했다.

1. `test_apply_preserves_source_count_when_current_diff_changes`
   - 원본 count는 1로 유지한다.
   - apply가 작성한 current diff는 2개가 되도록 만든다.
   - 두 수가 달라도 apply가 원본 count를 2로 덮어쓰지 않는지 확인한다.
2. `test_plan_rejects_source_inventory_count_mismatch`
   - 원본 registry count는 4다.
   - source inventory를 3개만 제공한다.
   - `build_reconstruction_plan`이 `ReconstructionError`로 차단하는지 확인한다.

반영 위치:

- `work/review-openmetadata-test-om-plan/harness/tests/test_registration_prep.py`
- `work/review-openmetadata-test-om-plan/harness/tests/test_vendor_rebuild.py`

## 4. 최종 변경 범위

최종 작업 트리에서 변경된 파일은 테스트 2개뿐이다.

```text
M harness/tests/test_registration_prep.py
M harness/tests/test_vendor_rebuild.py
```

코드·validator·충돌 테스트 파일은 A5 작업 전 기준 commit과 같아졌다.

변경하지 않은 범위:

- `build_reconstruction_plan` 구현
- `source-diff-paths.txt` 기준 불변식
- 제품 코드
- 활성 등록자료
- Git 설정
- `/om-plan` Skill 및 references
