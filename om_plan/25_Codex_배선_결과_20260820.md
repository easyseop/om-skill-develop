## 2. 기존 로직에 가한 최소 변경

`hook_cli.py`와 `hook_policy.py`를 배선만으로는 해결되지 않는 세 곳에 한해 수정했다.

1. 직접 슬래시 확장과 Skill 호출 경로를 같은 marker 정책에 연결.
2. 허용된 Bash plan 명령에 현재 Hook 세션 ID·상태 경로를 주입.
3. 독립 문서 판독 agent 한 종류만 read-only 보조 경로로 허용.
4. `/usr/bin/git`처럼 절대 경로로 호출해도 Git 변경 명령으로 인식하도록 실행 파일 이름을 정규화.

marker 생성·소유권·정리 로직과 `plan-validate`의 사실 재계산 로직은 변경하지 않았다.

## 3. UserPromptExpansion 판정

추가가 필요하다고 판단했다. Claude Code 공식 Hook 문서가 직접 슬래시 명령 확장을 `UserPromptExpansion`이라는 별도 이벤트로 제공하고, 이 경로는 Skill 도구의 `PreToolUse`만으로는 동일하게 다뤄진다고 단정할 수 없기 때문이다.

- 근거: <https://code.claude.com/docs/en/hooks>
- 별도 agent 근거: <https://code.claude.com/docs/en/sub-agents>

단, 실제 설치 환경에서의 이벤트 발생 순서는 아직 Claude 반례 검증 대상이다. 구현은 `UserPromptSubmit` 뒤의 `UserPromptExpansion`만 허용하고, expansion만 단독으로 들어오면 marker 우회로 보아 차단한다.

## 5. 남은 위험·미확인

1. 실제 Claude Code 앱에서 A~F의 4모드 반복 반례는 아직 실행하지 않았다. 단위·래퍼 검사와 실제 호스트 검사는 구분한다.
2. GitLab 관리 콘솔의 protected 변수·workspace trust 설정은 이 작업 트리에서 확인할 수 없다.
3. Hook은 Claude Code의 보조 강제선이다. Hook을 사용하지 않는 다른 실행 주체는 CI의 재수집 검증으로 차단해야 한다.
4. 배선 수용 기준 G 중 `changed_path_count`는 보강했지만, `provenance`·버전 source 전이는 Q10이 미확정이라 임의 구현하지 않았다. upgrade apply 의미가 결정된 뒤 별도 조치가 필요하다.
5. `approval`은 계획 검토 준비 상태일 뿐 배포 승인이나 제품 반영 권한이 아니다.
