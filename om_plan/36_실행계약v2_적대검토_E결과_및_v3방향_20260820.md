# 실행계약 v2 적대검토 — 리더 E(악용자) 결과 + v3 방향 (2026-08-20)

상태: 리더 E 완료. 리더 D(자유 해체) 세션한도 실패(6pm 리셋 후 재실행 가능). Codex 검토(지시서 34→결과 35) 미착수(사용자 전달 대기).

## 핵심 결론 — v2는 v1보다 낫지만 **같은 부류의 P0가 남음**

E가 코드로 재현한 v2 우회 5건(P0)·3건(P1)은 **전부 한 뿌리**: v2의 새 게이트가 **운영자가 스스로 채우는 선언 필드**(expected-paths 폭, observed diff 목록, 2차판독, verify-receipt completeness)에 신뢰를 얹는데, 그 선언의 **정직성을 기계가 재계산/재실행으로 반증하는 앵커가 로컬에 없다.** v2 §2가 정직하게 인정한 "로컬 위조 가능"이 곧 P0 공격면.

## E의 P0 (5건)

| ID | 우회 | 왜 안 잡히나 |
|---|---|---|
| A1 | **expected-paths 과대선언**(`src/**`) → observed ⊆ 항상 성립 → deviations 소멸 → 재계획 루프 무력화 | expected-paths 폭에 상한 없음(§2.2) |
| A2 | **observed_changed_paths 자기축소** — 앵커 밖 만진 파일 목록서 누락 | verify가 `git diff(base..impl)` 재계산해 대조하는 규칙 없음(§2.3) |
| A3 | **동작변경을 "앵커 밖 파일"로** → 교집합 ∅ → 보존 위장 | 앵커=과거 등록 changed_paths인데, 좁게 등록됐으면 실변경 파일이 교집합에 안 들어옴. 앵커 완전성 요건 없음 |
| A5 | **2차판독 로컬 자기위조** — review_context·digest·missing 다 자기기입 | §10 out-of-band는 "배선 목표"일 뿐 미구현. §9 "이중 증명"이 둘 다 같은 손 |
| A7 | **verify-receipt partial 세탁** — completeness 누락=[] 자기신고, partial verdict apply 가부 미정의 | partial의 apply 규칙 §2.3 공백 |

## E의 P1 (3건)

- A4 trivial mutant(파일 삭제)로 §5 형식 충족 — 실효성 0.
- A6 N/A "명시적 없음" 세탁(A5 의존, 범위선정 재량 악용).
- A8 기존 넓은 계약 재사용으로 §7 fail-closed 회피(신설 안 하면 게이트 발화 안 함, A3와 합성).

## E가 확인한 실재 방어 (유지) — 형식위조는 촘촘

완료 run 재작성 거부(COMPLETED_RUN_READ_ONLY), 자기참조 증거 차단, digest 위조 재계산 대조, 승인서 placeholder 거부, base 신선도 락 재확인, 신규 ID 계약 역결속. → **기존 코드의 "형식 위조" 방어는 견고.**

## v3 방향 (E의 D1~D6 + 뿌리 원칙)

**뿌리 원칙: "선언을 믿지 말고 재계산·재실행하라. 못 하면 사람/CI 앵커로."**

1. [A1/A2] **expected-paths 앵커-상한 강제** + verify가 `git diff(base..impl)` **재계산해 observed와 완전일치**(부분집합 아님) 요구. validate.py 재계산-대조 패턴(L465-484)을 tree diff로 확장.
2. [A3] **앵커 완전성**: change 보존판정의 교집합 상대를 "등록 changed_paths"가 아니라 **그 ID 커밋이 실제 touch한 net 경로 전체**로. 등록 앵커가 실 touch보다 좁으면 block.
3. [A5/A6] **2차판독 out-of-band를 upgrade approval 하드 전제로 승격**: CI가 별도 컨텍스트 기동→review 생산, proposal review와 byte 불일치 시 block. 로컬 단독은 review_pending까지만(사람 승인 필수).
4. [A7] **partial verdict apply 금지 명문화** + completeness는 verify 재계산 소유ID 전건과 대조(자기신고 금지) + CI가 contracts 재실행 대조.
5. [A4] **mutant 유의미성 하한**: 파일 전체 삭제/무효화류 금지, 국소 변조만 실효 mutant로 계수.
6. [A8] **동작변경 시 계약 신선도**: 인용 계약이 이번 변경경로를 커버하도록 개정/신설됐음을 요구. 무개정 재인용 시 required_human_actions 강제→§7 연결.
