## 확정된 개편 구조

1. **이 저장소가 하는 일** — 은행 커스터마이징을 기능 단위(BANK-OM-001~007)로 파일 관리,
   `/om-plan`이 그 관리 파일들의 버전업 갱신을 담당. "관리 파일=현황판, om-plan=현황판 갱신 도구".
2. **언제 무엇을 쓰나(4모드 표)** — initial(최초 등록)·feature(신규)·change(수정)·upgrade(버전업).
   upgrade가 주목적임을 명시.
3. **시작하기** — pytest 확인 + `plan start`/`plan check` (슬래시 명령 확정 전까지 실제 CLI로).
   결과 읽는 법(approval=사람 검토 준비, 배포 승인 아님). 상세는 docs/USAGE.md(예정).
4. **저장소 구조(참고, 맨 아래 표)** — 관리 파일을 맨 위에 강조, 나머지 압축.
5. 출처(clean export) 절 유지.

## 근거 (실측)

- 관리 파일: `harness/registrations/om-temp-1.13.1/manifests/BANK-OM-001~007.yaml` (7개 확인)
- 매니페스트 구조: customization_id·implementation·upgrade_watch·assurance·series
- 4모드: 스키마 enum [initial, feature, change, upgrade] (description 없음 → 우리 설계 문서가 정본)
