- **Q11 — 확정: 업그레이드 산출물 검증을 3층으로.** (기준 = 01A §4의 9개 산출물 = 체크리스트 CHK-1~9. watch는 제외 = 별도 게이트.) 초기 "존재만 강제" 안을 적대 검토로 폐기하고 아래로 격상. 이유: "존재+N/A+자기신고 라벨"은 checkbox 극장(가짜 사유로 N/A·아무 라벨 부착 가능)이라 위장만 만든다.
  - **층1 [검사기 결정론 — 못 속임]**: 사실-근거 커버리지 강제.
    - `path-remap`: 영향 경로(`official-upgrade-paths ∩ 등록 커스텀 경로`)를 **전부 커버**해야 함(shared_impact처럼 자동 교집합). 빠진 경로 → block.
    - `doc-code-crosscheck`: `official-doc-findings`의 각 항목이 crosscheck에 연결돼야 함(operations의 finding_id 연결 방식).
  - **층2 [LLM 2차 판독 — 검사기 아님]**: `official-doc-findings`·`operations`의 **문서 누락은 뒤 테스트가 못 잡으므로**(코드 아닌 배포 요구사항), 원문 snapshot을 **독립 LLM(별도 agent)이 다시 읽어** findings와 대조. 누락 발견 시 질문/차단. 사람 병목 없이 자동, 단 LLM이라 ground truth는 아님(누락 위험을 줄이되 없애지 못함 — 정직 고지).
  - **층3 [존재만]**: `upgrade-plan` 등 판단형 산출물은 비어있지 않은 존재만.

  - 근거: 코드 산출물은 뒤 테스트가 잡지만(사람검토 불요), **문서 완전성은 어떤 뒤 테스트도 안 잡아 운영에서 터짐**(05 문서 한계) → 층2로 메움.

## 신규 사람 결정 (임의 확정 금지)

### Q10 — upgrade 반영 경로 (갭 A4)

- 문제: 정책 §6은 "upgrade도 plan→승인→apply"라 하나, 구현된 apply(`registration_prep.py`)는 `source` 블록(`upstream_sha`/`upstream_tag`/`snapshot_sha`/`changed_path_count`)을 갱신하지 않는다. 등록 폴더는 버전별(`om-temp-1.13.1`)이라, 새 공식 버전의 등록 `source`를 **누가 만드는지** 정해져 있지 않다.
- 선택지:
  - (A) upgrade 반영을 apply가 하되, apply가 새 버전의 `source` 블록을 갱신하도록 확장.
  - (B) 새 공식 버전은 **새 등록 폴더를 bootstrap**으로 생성(기존 커스터마이징을 새 버전 위로 이관). apply는 동일 버전 내 변경만.
  - (C) 혼합: 커스터마이징 이관은 plan/apply, 버전 기준선 갱신은 bootstrap.
- 무엇을 막나: 이 결정 전에는 실제 upgrade 반영을 실행할 경로가 닫혀 있다.
- 권고: 정보 부족. 사람 결정 필요.

### Q11 — upgrade 필수 산출물의 검사기 강제 여부 (갭 A3) — ✅ 확정: 3층(커버리지+2차판독+존재), 위 "확정된 결정" 참조

(아래 (A)/(B)는 초기 논의 기록. 적대 검토로 "존재만"은 폐기되고 3층으로 격상됨.)

- 문제: 01A는 upgrade 출력으로 path-remap·doc-code-crosscheck·operations-checklist·shared-code-delta를 규정하나 검사기는 존재를 강제하지 않는다(path-remap 검증 0줄). 지금은 LLM 책임(upgrade.md에 명시).
- 선택지:
  - (A) 검사기가 mode=upgrade일 때 path-remap 등 필수 산출물 존재를 강제(Codex 조치 3).
  - (B) 강제하지 않고 LLM 책임 + 사람 검토로 둔다(현행). 05 문서가 "자동 검증 범위는 findings→checklist 연결까지"라 한 한계와 정합.
- 무엇을 막나: 없음(현행도 동작). 품질 보증 강도 결정.
- 권고: 최소 path-remap만이라도 (A) 검토. 나머지는 (B) 유지 가능.

## 기록 (결정 아님 — 추적성/주의)

### 기록-1: intent_review 게이트 (갭 A8 추적성)

- 사실: `preflight.py:316`가 `intent_review_required: true`를 설정하고 `ci/om_plan_ci.py:147`가 강제한다. 승인(approval) 전 사람이 의도를 확인하도록 하는 게이트다.
- 추적성: 설계 문서(00·01·01A·02·03·04·05·검토서)에 "intent" 문자열이 없다. **설계에 명명되지 않고 구현 단계에서 추가된 게이트**다. 기능은 안전측(사람 확인 강제)이라 무해하나, 설계-구현 추적성이 결여됐음을 여기 기록한다. (01A의 "approval=계획 검토 준비"·사람 STOP 취지와 정합)

### 기록-2: risk/patch-kill의 사람 입력 대기 (갭 A6)

- 사실: `risk`·`patch-kill` 명령은 사람이 작성하는 입력 파일(`change-intent.yaml`·`patch-kill-plan.yaml`)이 없으면 `require_file` 가드로 즉시 fail-closed한다(`om_workflow.py:685,768`).
- 판정: **설계된 동작**(사람 입력 대기)이며 버그 아님. 이 명령들을 쓰려면 사람이 먼저 해당 입력을 작성해야 함을 기록한다.

### 기록-3: 등록 파일 개정 이력 (이전 Q10안 해소)
