# 활성화 마커 — 계획 모드 차단 장치의 스위치를 누가 켜나

## 문제

`/om-plan` 중에는 Hook이 제품 코드 수정·git 상태 변경을 막아야 한다.
그런데 원래 설계(02 문서 초안)는 "Skill 실행 시 session state에 `mode=plan`을 기록한다"라고만 적었다 —
**기록 주체가 LLM**으로 읽히는 구조. 감시 대상이 감시 스위치를 쥐면, LLM이 기록을 생략(실수든, 저장소 파일에 심긴 주입 지시든)하는 순간 모든 차단이 비활성인 채 계획이 진행된다.

추가로 deny 목록에 `git checkout`·`switch`·`worktree add`·`fetch`가 빠져 있어서,
목록에 없는 명령으로 사용자의 working tree를 바꾸는 우회가 가능했다. (1차 검토 P0-1)

## 논의 경과 — 스위치를 켜는 주체 3단계

| 단계 | 방식 | 결함 |
|---|---|---|
| 1. AI가 켠다 | 지시서에 "1단계: 신호를 켜라" | 지시문은 강제가 아님. 건너뛰면 끝 |
| 2. 반드시 지나가는 명령이 켠다 | `plan-preflight`(사실 수집기)가 실행되며 마커 생성 — AI는 이 명령 없이 조사 자료를 못 받음 | **켜지기 전 빈 구간**: 사용자가 /om-plan 입력 → preflight 실행 사이. 이 구간엔 "om-plan 세션인지" 자체를 판별할 정보가 없음 |
| 3. 실행 환경이 켠다 | Claude Code의 `UserPromptSubmit` Hook이 사용자 입력 순간(AI가 읽기도 전에) 마커 생성 | **끄는 시점이 애매**: "비-om-plan 입력이 오면 해제"로 하면 계획 도중 사용자 질문 하나로 보호가 꺼짐. Claude Code 밖(CI·미설정 컴퓨터)에선 장치 자체가 없음 |

"CLAUDE.md 최상위에 적으면 되지 않나"도 검토 → 기각.
CLAUDE.md에는 이미 같은 규칙이 적혀 있었는데도 우회 가능 판정이 나왔다.
문제는 "적혀 있느냐"가 아니라 "안 지켰을 때 막는 것이 있느냐". 설계 문서 스스로의 원칙이기도 함
("설명은 Markdown, 강제는 코드와 Hook" — 02 §1).

## 결정 — 2계층 겹으로, 역할 분담

사용자 결정: "일단 둘 다 넣고 각각의 주의점을 고려해 최대한 안전한 쪽으로."

- **계층 1 (session marker)**: `UserPromptSubmit`이 `/om-plan` 입력 순간 생성. **켜기 전담** —
  비-om-plan 입력이 와도 해제하지 않는다(질문으로 꺼지는 구멍 차단). 2단계의 빈 구간을 메움.
- **계층 2 (run marker `.plan-active`)**: `plan-preflight`가 기계 파일을 **모두 쓴 뒤 마지막에** 생성.
  어느 run 폴더가 진행 중인지 식별. 3단계가 모르는 작업 단위·종료 시점을 담당.
- **default-deny**: session만 있고 run이 없으면 preflight 실행 외 전부 차단.
  둘 다 있으면 현재 run의 `proposal/` 쓰기만 허용. → 마커를 안 만들어서 얻는 이득이 없음.
- **해제**: `plan-validate`가 성공·실패 무관 결과 기록 후 두 마커를 정리(멱등).
  preflight 실패로 run marker가 없어도 cleanup 경로가 session marker를 해제.
- **deny 목록 확장**: checkout·switch·branch 변경·worktree add/remove/move/prune·fetch 추가.

## 고려한 것

- LLM이 만든 파일은 어느 마커로도 인정하지 않는다 (마커 위조 차단).
- Bash 문자열 정규식 한 개로 명령을 검사하지 않는다 — tokenize 또는 workflow CLI 한정.
  `git -C`·절대경로·인용부호·compound command·symlink·alias 우회를 반례로 시험.
- **Hook은 Claude Code 안에서만 동작한다는 한계를 숨기지 않는다** — CI·미설정 환경의 최후 안전망은
  Hook이 아니라 `plan-validate` 재계산(→ `02_사실파일_위조검증.md`)이며, 이 의존은 선택이 아니라 의무.
