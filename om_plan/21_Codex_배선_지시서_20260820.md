작성일: 2026-08-20
작성자: Claude(검증자·기록자). 이 문서는 명세다. 구현은 Codex가 한다.
대상 저장소: 검사기 `kb-datacatalog-upgrade-checker`(GitLab: datacatalog/kb-datacatalog-upgrade-checker).

## 0. 한 줄 요약

`/om-plan` SKILL.md가 "말로만" 막는 위험을, **이미 존재하는 하네스 로직을 `.claude/`에 연결**해 실제로 강제한다. **로직을 새로 만드는 게 아니라 설치·배선**이 핵심이다.

## 1. 배경 — 이미 구현돼 있는 것 (새로 만들지 말 것)

아래는 검사기 하네스에 **이미 있다**. 재구현 금지. 연결·설치만 한다.

- `harness/acgh/plancore/hook_cli.py` — Claude Code 훅 어댑터. 이벤트 처리:
  - `UserPromptSubmit`: 세션 marker 생성. 세션에 이미 active planning run이 있으면 거부.
  - `PreToolUse`: marker 검사 후 미승인 도구 호출 거부.
  - `Stop`: 종료 시 결정·거부 처리.
  - 독스트링 명시: "installable infrastructure, not an installed project hook. installation under a project's control directory is a later, separately approved step." ← 이 문서가 그 단계다.
- `harness/acgh/plancore/markers.py` — `create_session_marker`, `session_marker_path`, `load_session_marker`.
- `harness/om_workflow.py` — `plan start`가 세션 marker 생성·신뢰 digest 기록(`record_trusted_input_lock_digest`), `plan check`가 marker 검증(오늘 실증: marker 없으면 `RUN_MARKER_INVALID`로 fail-closed). `apply --proposal --approval`는 이미 승인서를 필수 인자로 요구.
- `.gitlab-ci.yml`, `.github/workflows/om-plan-ci.yml` — CI 파이프라인 이미 존재.

세션 식별은 `OM_PLAN_SESSION_ID` 환경변수(`select_plan_session_id`)로 주입된다.

## 2. 할 일 (배선 4건)

각 항목은 근거 파일을 명시했다. `.claude/`가 아직 없으므로 새로 만든다.

### 2-1. 훅 설치 — `.claude/settings.json`에 hook_cli.py 연결 (P0)

- 근거: `hook_cli.py`(UserPromptSubmit/PreToolUse/Stop 처리), `main()`이 stdin으로 hook payload를 받고 state_root 인자를 쓴다.
- 할 일: `.claude/settings.json`의 `hooks`에 위 3개 이벤트를 hook_cli.py 실행으로 등록. state_root(런타임 상태 디렉터리)를 인자/환경으로 전달. `OM_PLAN_SESSION_ID` 주입 경로 확정.
- 목적: 세션 marker가 자동 생성되고, marker 없는 plan check·도구 호출이 default-deny 되도록 만든다.

### 2-2. 사용자 직접 `/om-plan` 경로 통제 검토 (P1)

- 근거: 작성표준 02 CC-21 — 사용자가 프롬프트에 직접 친 `/명령어` 확장은 `PreToolUse`만으로 통제되지 않을 수 있다.
- 할 일: 사용자 직접 `/om-plan`과 Claude의 Skill 호출 **두 경로 모두** marker·승인 정책이 우회되지 않는지 판정. 필요하면 `UserPromptExpansion` 훅을 추가(hook_cli.py는 현재 미지원 이벤트이므로 확장 필요 여부를 판단). 불필요하면 "UserPromptSubmit+PreToolUse로 충분"을 근거와 함께 기록.

### 2-3. apply 등 반영·배포 권한 차단 (P0)

- 근거: `om_workflow.py`의 `apply`·`bootstrap`·배포 관련 서브명령.
- 할 일: `.claude/settings.json`의 `permissions`에서 apply/반영/배포 명령을 기본 `ask` 또는 `deny`로 둔다. `/om-plan`은 계획까지만이므로, 같은 세션에서 반영이 자동 실행되지 않게 한다.

### 2-4. Python 3.11+ 실행 보장 (P1)

- 근거: `harness/pyproject.toml` `requires-python >=3.11`, 하네스가 `datetime.UTC` 사용 → 3.9에서 즉시 ImportError(오늘 실증).
- 할 일: 하네스 실행 래퍼(또는 훅/설정)가 인터프리터 버전을 확인하고, 3.11 미만이면 **암호적 ImportError가 아니라 명확한 사전 오류**를 낸다. 필요 의존성(PyYAML·jsonschema·pathspec)도 함께 점검.

### 2-5. apply의 관리 파일 자동 파생 보장 (P1, 별도 관심사)

- 근거: `references/management-files.md`가 정한 [자동] 항목(승인 시 시스템이 갱신해야 하는 필드)과, 실제 apply 구현 `harness/prepare_registration.py`(이 clean-export 저장소엔 없음).
- 배경: `/om-plan` 후보는 제안까지만 하고, `status`(proposed→active)·`owner_status`·`snapshot_sha`·`upstream_*`·`changed_path_count`·`ancestry_preserved`·`provenance`·`unregistered_findings`·`shared-path-owners`·`commit-inventory`·diff 목록은 **승인(apply) 시 자동 갱신**돼야 한다.
- 할 일: `prepare_registration.py apply`가 위 [자동] 항목을 실제로 갱신하는지 확인하고, 누락 항목이 있으면 갱신하도록 보강한다. 특히 `provenance`가 change/feature/upgrade 반영 후에도 `source-snapshot`으로 남지 않게 한다(사용자 지적 gap).
- 주의: 이건 enforcement 배선이 아니라 apply 정확성 문제다. 별도로 다뤄도 된다.

## 3. 금지사항

- hook_cli.py·markers.py·validate.py 등 **기존 로직을 임의 변경 금지**(연결·설치만). 로직 수정이 꼭 필요하면 이유를 결과 파일에 근거와 함께 남기고 diff 보존.
- **push 금지.** 커밋도 하지 말고 작업 트리 변경만 남긴다(Claude가 검증 후 반영 대행).
- **/om-plan SKILL.md·references 변경 금지**(그건 Claude 소유·검증 완료본). 이 배선은 `.claude/settings.json`·훅 연결·권한·래퍼에 한정.
- 기존 `.gitlab-ci.yml`·`.github/workflows/*` 정책을 약화하지 않는다.
- 확인 못 한 동작을 사실처럼 단정하지 않는다.

## 5. 수용 기준 — Claude가 반례 없이 검증할 항목

Claude가 아래를 다중 반례로 검증한다. **하나라도 반례가 통과하면 미완**으로 되돌린다.

| # | 정상(통과해야) | 반례(반드시 차단돼야) |
|---|---|---|
| A. 세션 marker | UserPromptSubmit→plan start→plan check 정상 approval | 세션 marker 없이 plan check → 거부(RUN/SESSION marker invalid) |
| B. 중복 run | 새 세션에서 새 run | 한 세션에 active run 있는데 또 UserPromptSubmit → 거부 |
| C. PreToolUse | marker 있는 상태 도구 호출 허용 | marker 없이 도구 호출 → deny |
| D. apply 차단 | 승인 흐름 정상 | 승인서·권한 없이 apply → 차단 |
| E. 직접 호출 우회 | 두 경로(사용자 직접 /om-plan, Claude Skill) 정책 동일 | 한 경로로 marker·승인 우회 시도 → 양쪽 다 차단 |
| F. Python 버전 | 3.11+ 정상 동작 | 3.9 실행 → 명확한 버전 오류(암호적 ImportError 아님) |
| G. apply 자동 파생 | change 승인 후 status=active·provenance 갱신·changed_path_count 재계산 | 승인 후에도 provenance가 source-snapshot로 남거나 파생 필드가 낡음 |

각 항목마다 정상 1건 + 반례 최소 1건을 실제 실행으로 확인한다. 4모드(initial·feature·change·upgrade) 각각에 대해 A~F를 반복한다.
