## 2. 현재 코드 상태 (자동 아님)

commit `1f02e1d3` 기준으로 지금 있는 것은 두 개뿐이다.
- `plan-preflight`가 준비 결과에 `input_lock_digest`를 출력한다.
- `plan-validate`가 `--expected-input-lock-digest`를 인자로 받는다
  (누락·형식오류·불일치 → `analysis_error`, 일치+정상 → `review_state=review_ready`).

**빠진 것:** 이 지문을 자동으로 보관했다가 검사 단계로 넘기는 배선이 없다. 지금은
사람이 손으로 옮겨야 한다. 이번 작업의 목표가 바로 이 배선을 자동화하는 것이다.

## 3. 이번 작업 목표

**preflight가 낸 지문을 CI가 보관했다가 최종 validate에 자동으로 넘기는 파이프라인을
구축하라.** 코드 로직(validate/preflight)은 이미 갖춰졌으므로, 원칙적으로 **CI 배선**이다.

권장 흐름:
```
job A (preflight)  plan-preflight 실행 → input_lock_digest를 CI 보호 저장에 캡처
                    (동시에 intent_summary를 사람/승인 게이트에 노출 — §5)
job B (plan)        LLM이 proposal 작성 (비신뢰 구간)
job C (validate)    job A가 저장한 digest를 꺼내
                    plan-validate --run-dir ... --expected-input-lock-digest <digest>
                    종료 코드로 판정
```

## 4. 반드시 성립해야 할 수용 조건 (하나라도 깨지면 무력)

1. **지문은 repo 파일이 아니라 CI 자체의 보호 저장(job output/artifact/secret)에 둔다.**
   LLM 단계가 쓸 수 있는 저장소 파일·환경변수에 두면, 계획 조작 + 지문 위조가 함께 가능해
   보호가 사라진다(검토 시나리오 7).
2. **LLM 계획 단계는 (a) 워크플로 정의 파일, (b) job A가 저장한 digest, (c) validate에
   넘길 expected 값을 수정할 수 없어야 한다.** "한 파이프라인"이라는 것만으로는 부족하고,
   이 쓰기 경계가 핵심이다.
3. **판정은 fresh `plan-validate`의 종료 코드/출력으로 한다. run 디렉터리에 남는
   `validation-result.json` 파일 바이트를 신뢰하지 않는다.** 검사기는 기존 결과 파일의
   무결성을 검증하지 않으므로(검토 P2-2), 공격자가 가짜 approval 결과를 선주입하면 파일을
   믿는 소비자는 속고, 정식 검증이 `COMPLETED_RUN_READ_ONLY`로 막히는 denial도 가능하다.

## 5. 구현 시 지킬 세부

- **upgrade 모드도 단일 지문으로 충분하다.** `official_doc_sources_digest`가 이미
  `input_lock_digest`에 편입돼 있어(검토 시나리오 6 확인), 문서 bytes까지 그 하나로 커버된다.
  별도 facts digest 전달은 필요 없다.
- **exit code 매핑은 기존 유지**(pass=0, block=1, approval=2, analysis_error=3).
  CI는 `analysis_error(3)`·`block(1)`을 실패로 처리한다. `approval(2)`을 "사람 검토 필요"로
  어떻게 라우팅할지는 **Q9(보류)**이므로 여기서 임의 확정하지 말고, 최소한 자동 통과(0 취급)로
  뭉개지 않게만 한다.
- **preflight의 `intent_review_required`/`intent_summary`/`operator_action`을 CI가 노출한다.**
  E안은 preflight "이후" 바꿔치기만 막는다. **preflight를 잘못된 run-request로 시작한 경우는
  보호하지 않으므로**, job A의 intent_summary(요청 refs·고정 SHA·모드 등)를 사람/승인 게이트가
  확인하는 단계를 넣는다. 이걸 "E가 사람의 사전 판단까지 보증한다"고 표시하지 말 것.
