# [다른 세션용 지시서] test-agent 신규사용자 검토 피드백 — 고칠 것

작성일: 2026-08-24. 출처: 제3자 신규사용자 관점 실측 검토(문서만 따라 설치→데모→버그모드 전부 실행). 대상 저장소: `easyseop/test-agent`.

> 이 지시서는 test-agent 저장소에서 작업하는 Claude 세션에 그대로 전달한다.

## 검토 결론 (참고)

**조건부로 바로 사용 가능** — Python 3.11+만 확인하면 문서만 따라가서 설치→데모(통과21/실패0)→버그검출(실패7건, exit 1)까지 전부 첫 시도 성공. 아래는 그 "조건부"를 없애기 위한 수정 목록이다.

## 건드리지 말 것 (실측으로 잘 됨이 확인된 것)

- 3.11 환경에서의 설치 흐름(`pip install -e ".[db,dev]" -c constraints.txt` → exit 0)
- 데모 자가확인(`./scripts/run_demo.sh` → 통과 21·실패 0, 35.3s, 리포트/절차서/비디오/트레이스 생성)
- 버그 주입 모드 검출력(UI↔DB 불일치 76vs37·경계일 누락 3건·JS 오타·반응형 오버플로 원인요소 지목·404 링크 — **실패 7건, 종료코드 1 직접 캡처 확인**)
- run_demo.sh의 종료코드 전달(86→97행)
- 문서 체계 자체(README 검증표·QUICKSTART·04-config-walkthrough의 0→실행 안내)

## 고칠 것 (우선순위순)

### 1. [중] USER_GUIDE 설치 섹션에 Python 3.11 확인 + venv 절차 추가
- 현상: `docs/USER_GUIDE.md` §설치(53행 부근)에 **pip 명령 2줄만** 있음 — venv도, Python 버전 요구도 없음.
- 문제: **비개발자 대상 문서**인데, macOS 기본 `python3`(예: 3.9.6)로 그대로 실행하면 아래 2번의 엉뚱한 에러를 정통으로 맞는다.
- 수정: QUICKSTART §1과 동일하게 "Python 3.11 이상 확인(`python3 --version`) → venv 생성·활성화 → pip install" 순서로. 비개발자 눈높이 한 줄 설명 포함.

### 2. [중] 구버전 Python 진입 시 오류가 원인을 알려주지 않음
- 재현(실측): python3.9 venv에서 문서의 pip 명령 실행 →
  ```
  ERROR: File "setup.py" or "setup.cfg" not found. Directory cannot be installed in editable mode
  (A "pyproject.toml" file was found, but editable mode currently requires a setuptools-based build.)
  ```
  (구버전 pip 21.x가 PEP 660 editable 미지원 — "Python이 낮다"는 말이 어디에도 없음.)
- 수정 (둘 다 권장):
  - (a) **run_demo.sh 첫머리에 Python 버전 체크** — 3.11 미만이면 `"Python 3.11 이상이 필요합니다 (현재 X.Y). QUICKSTART §1 참조"`로 명확히 exit. (run_demo가 자가확인 진입점이므로 여기서 잡는 게 효과 최대.)
  - (b) QUICKSTART/README에 **트러블슈팅 1항목**: "위 setup.py 에러가 나면 = Python/venv가 구버전" 안내.

### 3. [소] README 설치 섹션에 Python 3.11+ 요구 한 줄
- 현상: 버전 요구가 QUICKSTART에만 있고 README `## 설치`(pip 2줄)에는 없음. README에서 바로 설치로 진입하는 사용자가 놓친다.

### 4. [미미] README 버그 모드 수치 정리
- 현상: README는 "심어둔 버그 6건 검출"이라 쓰는데 실측 결과는 **실패 7건**(버그 하나가 단언 실패+스윕 예외 등 실패 2건으로 표출).
- 수정: "버그 6개 → 실패 7건으로 검출" 식으로 수치 관계를 명시하거나 표기 통일.

## 수정 후 검증 방법

1. python3.9(또는 임의 <3.11) venv에서 `./scripts/run_demo.sh` → **명확한 버전 안내로 즉시 종료**하는지.
2. 3.11 venv에서 데모 회귀: 통과 21·실패 0 유지.
3. `--bug` 모드 회귀: 실패 검출 + 종료코드 1 유지.
4. USER_GUIDE만 보고 (QUICKSTART 안 보고) 처음부터 따라갔을 때 막히는 곳이 없는지 자체 점검.
