# A-3 명세 — change 관측 분기 (2026-08-20)

트랙 A 2항목. **범위: change `post_change_reconcile`의 검사기 판정 하나.** pre_plan·upgrade·verify 실행은 별개. A-4(per-ID facts) 위에 얹는다.

## 0. 원칙 (v2 붕괴·패널 교훈 반영)

- **자기신고 금지**: `change_kind` 필드 도입 안 함. 보존/변경을 **관측(observed diff ∩ 그 ID 앵커)으로 판정**한다.
- **사실-근거만 강제**: 판정은 두 fact의 교집합(둘 다 위조 어려움 — observed는 git diff, 앵커는 등록자료). **의미 품질(계약 delta가 맞나)은 강제 안 함**(downstream verify·사람 — 정직 고지).
- **shared-path-owners 등가검사 금지** (A-4 리뷰어 P1): 포함관계만.

## 1. 입력 (facts)

- `observed-change-paths` (기존): `custom_baseline`→`candidate` 순변경 경로(제품 repo). 요청 `customization_id` 대상.
- `customization-relations` (A-4): 그 ID의 `changed_paths`·`required_changed_paths`·`contracts`·`tests`.
- `shared-path-owners` (기존): 큐레이션 공유 소유자맵.

## 2. 판정 (검사기 결정론 — collectors.py validate_proposal의 change 블록)

요청 `customization_id`=X, `A` = customization-relations[X]. `O` = observed-change-paths 집합.

정의:
- `O_req = O ∩ A.required_changed_paths` (load-bearing 교집합)
- `O_surface = O ∩ A.changed_paths` (그 ID 전체 표면 교집합)
- `O_shared = O ∩ shared-path-owners.keys()` (공유 경로 교집합)
- `O_outside = O − (A.changed_paths ∪ shared-path-owners.keys())` (그 ID 표면·공유 밖)

강제 규칙(어기면 block):

1. **동작변경 신호 → 계약 delta 필수.** `O_req ≠ ∅`이면(필수 경로가 바뀜) proposal에 `contracts-delta`(그 ID 계약의 신설/개정)가 있어야 한다. 없으면 block. (delta의 *내용* 정확성은 강제 안 함 — §4 한계.)
2. **표면 밖 변경 → STOP.** `O_outside ≠ ∅`이면(그 ID 등록 표면·공유 어디에도 없는 경로가 바뀜) — 등록이 불완전하거나 변경이 범위 밖. proposal에 그 경로들을 담은 unresolved-question + `next_step_blocked: true` 없으면 block. (Codex P1-3 "좁은 앵커 우회" 차단: 앵커 밖은 조용히 보존으로 못 넘어감.)
3. **보존 후보라도 테스트 재실행 계약.** X의 `A.tests`(그 ID 등록 테스트)가 전건 `contracts-to-run`에 있어야 한다. 없으면 block. (실제 실행은 verify — 계획 단계는 목록 강제.)
4. **공유 영향.** `O_shared ≠ ∅`이면 그 경로의 소유자(shared-path-owners 값)를 `shared_impact`에 선언. 기존 shared 규칙과 동일. **등가검사 아님 — O_shared는 O ∩ (등록된 shared 키)라 이미 부분집합.**

분기 요약(참고, 강제는 위 규칙):
- `O_req ≠ ∅` → 동작변경: 규칙1(delta)+규칙3(테스트).
- `O_req = ∅` ∧ `O_surface ≠ ∅` → 보존 후보: 규칙3(테스트 재실행).
- `O_outside ≠ ∅` → 규칙2(STOP).

## 3. 하위호환 / 범위

- 기존 change 검사(customization_id 등록 여부·floor·evidence)는 유지. 위 규칙 추가만.
- pre_plan(관측 없음): 이 판정 적용 안 함(observed-change-paths 부재). 규칙은 post_change_reconcile 한정.
- upgrade·feature·initial: 이 블록 진입 안 함(mode/change_path 가드).
- `/om-plan` SKILL·references·apply·제품코드·활성 등록자료 미수정.

## 4. 정직한 한계 (강제 안 하는 것 — 명시)

- **계약 delta의 의미 정확성**: "정말 바뀐 동작을 반영한 계약인가"는 검사기가 못 본다(판단). D9 경고대로 `contracts-delta` "존재"만으로 통과하면 새 체크박스가 된다 → delta의 meaningful을 **"계약 필드(invariant/required_tests)가 실제로 변화"**로 정의(존재만 아님). 그래도 내용 타당성은 downstream verify·사람.
- **테스트 실제 실행**: 계획 단계는 `contracts-to-run` 목록 강제까지. 실행·통과는 verify(downstream).
- **관측=동작변경의 근사**: 경로가 바뀌었다고 반드시 동작이 바뀐 건 아님(주석·포맷). 그래서 규칙1은 "delta 필수"지 "동작변경 확정"이 아니라, 사람/verify가 delta를 검토하게 하는 게이트다.

## 5. 수용 기준 (Claude 반례 검증)

| # | 정상 | 반례(block돼야) |
|---|---|---|
| 1 | O_req≠∅인데 contracts-delta 있음 → 통과 | O_req≠∅인데 delta 없음 → block |
| 2 | O_outside≠∅인데 그 경로 질문+STOP 있음 → 통과 | O_outside≠∅인데 조용히 보존 주장 → block |
| 3 | 그 ID 테스트 전건 contracts-to-run에 있음 | 일부 누락 → block |
| 4 | O_shared 소유자 선언 정합 | 누락 → block |
| 5 | **shared-path-owners와 등가검사 안 함** — O_surface가 shared보다 넓어도 정상 | 등가로 검사해 정상 데이터 거짓 실패 → 실패 |
| 6 | contracts-delta의 invariant/required_tests 실제 변화 | 빈 껍데기 delta(필드 무변화) → block |
| 7 | pre_plan엔 규칙 미적용 / 다른 모드 미진입 | pre_plan·upgrade에 규칙 발동 시 실패 |
| 8 | 기존 change 테스트 회귀 0 | 회귀 시 실패 |
| 9 | 좁은 앵커 우회 시도(앵커 밖 헬퍼 변경) → 규칙2로 STOP | 앵커 밖인데 보존 통과 → 실패 |
