# Codex 개발요청 — 사람 결정 요청 "표준형식" 강제 (백로그 #9)

작성일: 2026-09-02. 근거: 사용자 지적(2026-08-26) + 재지시(2026-09-02). 성격: 지금은 세션 관행일 뿐 시스템 강제가 아니라, 세션이 바뀌면 안 지켜질 수 있음. 이를 스킬·감사로 강제.

## 문제
검사기가 block/analysis_error/approval을 낼 때, 세션이 그 결과를 **항목 나열**만 하면 비개발자는 무슨 오류인지·뭘 골라야 하는지 모른다. 사람이 구조를 모를 수 있으므로 **선택지와 권고를 제시**해야 한다. 현재는 CLAUDE.md 관행(plain-report·two-track-report)으로 세션이 자발적으로 지킬 뿐, SKILL.md·검사기·감사 어디에도 강제가 없다.

## 요구 — SKILL.md(om-plan/apply/verify) 보고 형식에 다음을 명세로 넣고, 감사 rubric으로 검사
사람 결정이 필요한 모든 지점(비자명한 block·analysis_error·approval·선택 분기)의 보고는 아래 구조를 **반드시** 포함한다:
1. **최상단 3줄 요약** — (무슨 일 / 현재 상태 / 사람이 할 일)
2. **쉬운 설명** — 기술용어는 유지하되 "즉, ~입니다" 의역 병기(비개발자 기준)
3. **선택지** — (A)/(B)/(C) 형태로 사람이 고를 수 있는 실제 옵션
4. **각 선택의 결과** — 옵션별로 무엇이 일어나는지
5. **권고 + 주체 + 근거** — "권고: (X). 권고 주체: 저(실행 에이전트). 이유: ..."

## 반례(감사가 잡아야 할 것)
- 선택지 없이 오류 원문만 나열 → FAIL
- 권고에 주체·근거 없음 → FAIL
- 3줄 요약 없음 → FAIL
- 정상(모든 요소 포함) → PASS
