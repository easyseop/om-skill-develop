## 1. 결과

`decisions[]`의 필수 필드가 존재하기만 하면 값의 타입이 잘못돼도 지나가던 A-2 구멍을 보강했다.

- `subject`와 `decision`은 공백이 아닌 내용이 있는 문자열만 허용한다.
- `evidence_refs`는 리스트만 허용한다.
- `affected_customization_ids`는 모든 원소가 문자열인 리스트만 허용한다.
- `required_follow_up`은 리스트 또는 정확한 문자열 `"none"`만 허용한다.
- 필드가 없으면 새 타입 오류를 추가하지 않고 기존 `missing` 오류만 유지한다.
- 기존 `decision_source` enum과 evidence ref 원소·포인터 검사는 변경하지 않았다.
- commit·push·MR은 수행하지 않았다.

### 수용 기준 3의 정합성 차이

지시서는 `evidence_refs`의 잘못된 타입을 `block`으로 요구하면서 수정 범위를 `_validate_required_decision_fields` 한 함수로 제한한다. 현재 실행 순서는 `_validate_refs`가 타입 함수보다 먼저다. 따라서 이 한 함수만 수정하면 새 타입 issue는 만들어지지만 전체 판정을 `block`으로 바꿀 수 없다.

실측 결과:

```text
evidence_refs: "bad"
→ 전체 verdict: analysis_error
→ reason: EVIDENCE_REFS_INVALID: evidence_refs must be a list
```

현재도 잘못된 입력이 통과하지 않는 fail-closed 동작은 유지된다. 정확히 `block`으로 통일하려면 후속 검토에서 validation 호출 순서 또는 타입 오류가 있을 때의 evidence ref 검사 실행 규칙을 바꿔야 한다. 이는 지시된 한 함수 범위를 벗어나므로 이번 작업에서는 변경하지 않았다.
