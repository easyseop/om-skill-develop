# Codex 핫픽스 지시 — verify 시작 조건과 apply 성공 조건의 배타 모순

작성일: 2026-09-02. **실기동 확정 모순(3호)**: verifycore/workflow.py:172-176이 ① checker HEAD == apply-result 기록 sha ② 워크트리 clean 을 동시 요구. 그러나 apply는 관리파일(must_change 9건)을 반드시 미커밋 변경으로 남겨야 성공(management_three_way) → **apply 정상 완료 시 verify 시작 불가**. 커밋하면 ①(VERIFY_CHECKER_SHA_MISMATCH), 되돌리면 :179 registration_final_digest 대조(VERIFY_REGISTRATION_DIGEST_MISMATCH)로 막힘 — 세 경로 전부 폐색, 서버 실기동 원문 확보됨.

대상: clean-export 작업트리(main 기준). **커밋·push·MR 금지**(Claude 검증 후 대행).

## 요구사항 — 완화가 아니라 정밀화

1. **허용 조건**: verify 시작 시 dirty 경로가 있으면, 그 전부가 (a) 활성 등록부의 관리파일 경로이고 (b) 각 파일의 현재 내용 digest가 apply-result binding의 `management_file_digests` 기록값과 **정확히 일치**할 때만 통과. 하나라도 다르면 기존대로 VERIFY_CHECKER_DIRTY(사유에 불일치 경로 명시).
2. **불변**: 관리파일 외 경로의 dirty는 기존대로 차단. checker HEAD 동일성 검사(:172-174)와 registration_final_digest 대조(:179)는 그대로 유지.
3. **반례 테스트**: ① clean+digest 일치 → 통과(기존 유지) ② 관리파일 dirty·digest 일치 → 통과(신규 — 이번 실기동 상태) ③ 관리파일 dirty·digest 불일치 → 차단 ④ 비관리파일 dirty → 차단 ⑤ HEAD 변경 → VERIFY_CHECKER_SHA_MISMATCH 유지 ⑥ 전체 스위트 green.
4. **점검 요청**: 리허설(81)에서는 verify가 통과했는데 이 검사에 왜 안 걸렸는지(당시 코드에 이 게이트가 없었는지, 관리파일 상태가 달랐는지) 원인을 결과서에 한 절로 밝혀라 — 회귀 여부 판단에 필요.
