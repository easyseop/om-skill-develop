# om-verify 구현 지시서 (v1)

작성일: 2026-08-24. 작성자: Claude. 구현: Codex.
정본: 이 문서가 om-verify v1 구현의 정본. 설계 `73` + 적대검토 `75`(P0 5건) + 사람 결정(V-1~V-3·test-agent 채택)을 통합. **충돌 시 이 문서를 따른다.**

> ★ **아직 구현 착수 신호 아님** — 착수는 별도 지시 후.

## ★★ 반드시 지킬 것 (반복 실수 방지)

1. **코드로 확인 전 단정 금지** — 옛 실행기·apply 산출물·lab 상태를 실측 후 사용.
2. **적대검토(75)의 P0 5건·P1 4건·반례 OV-01~14 하나도 빠뜨리지 말 것** — §아래와 75를 대조.
3. **옛 자산 이관 시 현재 정책 부합 재확인**(direct_tests 계약-only·per-ID 관계 등).
4. "테스트 N개 green"으로 완료 주장 금지 — 반례가 거짓 verified를 실제로 막는지.
5. v1 범위만(§7 후속 항목 구현 금지). commit·push·MR 금지(작업트리만).

## 0. 확정 결정 (구현 고정)

- **V-1 = C(혼합)**: 평시 상주 lab 배포 + 릴리즈 fresh compose. 환경↔candidate 기계 결속 필수.
- **V-2 = 핵심 화면부터 + API 정답원** / **V-3 = 기본 fail + 승인된 예외 artifact만**.
- **test-agent = UI층 부품**(계약 I/O 뒤 교체가능). 본체는 pytest.
- 패키징: **clean-export 편입**(om-apply와 동일).
- 최종 상태 3종: `verified(0)` / `failed(1)` / `infra_error(3)` — **infra_error·부분실행·skip·WARN은 절대 verified 아님.**

## 1. 본체 구현 (P0 반영)

### ① 인계 재검증 (P0-1·P0-2)
- 입력 = **`apply-result.json` 전체** + 모든 binding digest(plan·apply context·result·등록자료 최종·관리파일별·checker SHA). 축약 handoff 금지.
- 전부 **재계산 대조**. 어긋나면 stale/tampered로 `infra_error`.
- **required_tests는 인계값이 아니라, apply가 기록한 등록자료 digest에 해당하는 고정 스냅샷에서 ID→계약→required_tests 재계산.** 인계값과 다르면 중단.
- **affected active ID 중 유효 테스트 0개가 하나라도 있으면 verified 금지**(OV-01).

### ② 환경 기동·결속 (P0-3·P1-1, V-1=C)
- **build receipt**: 신뢰 빌더가 clean detached checkout 확인 → {candidate commit/tree·dirty 여부·dist digest·**immutable image ID/digest**·OCI revision}을 한 receipt로. deploy는 **image ID로만**(tag 금지).
- verify 실행 직전: **container가 쓰는 image ID ↔ build receipt ↔ candidate** 삼자 대조. endpoint `/api/v1/system/version` revision은 **보조 교차확인만**(자기소개는 증명 아님).
- **run 격리 결속**: compose project·config 경로·container ID·volume/fixture digest를 run에 기록. 릴리즈 fresh는 run 전용 project/port/volume.
- 실측 주의(75 §4.1): 현재 lab은 지정 체크아웃≠실행 이미지 상태 — **이 상태를 그대로 신뢰하는 코드 금지**, preflight에서 불일치 시 중단(OV-13·14).

### ③ pytest 실행 (P0-4)
- **옛 실행기 이관·재사용**(새로 짜지 말 것): 완전본 트리 `harness/acgh/pytest_runs.py`(JUnit·0건·skip·exit 대조)·`testruns.py`(유효 0개·candidate/suite 결속)·`result_io.py`(canonical·원자 저장, 부분).
- 보강: **`PYTEST_ADDOPTS` 등 주입 env 제거**(-k/deselect/plugin 차단, OV-07) · **selector→concrete nodeid 수집 집합과 실행 집합 정확 대조** · `retries=0` 명시 · JUnit/log를 run ID에 결속(OV-08).
- skip·0건·부분·exit/JUnit 불일치 → verified 금지(OV-06). 계약 종류(API live/browser/source-static) **분리 집계**해 보고(P1-4).

### ④ UI층 부품 — test-agent (P1-2)
- 계약 I/O만: 입력 YAML(스키마 검증) / 출력 report.json·JUnit·exit.
- 시나리오는 **후보 코드와 분리 보관** + 각 기대값에 요구사항/Contract 참조·사람검토 연결. config/scenario digest를 receipt에 결속.
- **WARN(재실행 성공 포함) → verified 금지**(OV-11). 동어반복(UI·API 같은 오류 공유) 한계는 **"표시 일치 증거"로 한정 명시** + 사람 검토 항목(OV-10). 시나리오 0개 → infra_error.
- 부품 부재/실패 시 본체만으로 verify 성립(부품은 별도 게이트 합산).

### ⑤ receipt (P0-5)
- **canonical payload 하나**에: apply result·plan digest / 제품 repo ID·candidate commit/tree / checker repo ID·SHA·suite digest / 등록자료·관리파일 digest / build receipt digest / container·image ID·endpoint rev / compose·volume·fixture digest / 재계산 selector 전체+concrete nodeid / selector별 결과·시각·exit·JUnit/log digest / UI 부품 버전·config·report·trace digest / 예외(waiver) artifact digest / run ID·nonce·시각·판정.
- **재사용 단위 = "모든 결속 입력이 같은 완전한 run"** — 코드 SHA만 같다고 재사용 금지(OV-09). 완료 receipt 읽기전용.
- **정직 명시(v1 한계)**: digest는 무결성이지 진위가 아님. v1은 로컬 발행 + 이 한계를 receipt와 문서에 명시. **보호된 CI 발행/서명은 후속(§7)** — verified 표기에 "local-issued"류 신뢰 등급 포함.

### 판정 (P1-3)
- 모든 결과에 고정 `reason_code` + 게이트별 `execution_status`.
- 반복 infra_error → 정해진 횟수 후 사람 escalation 기록(OV-12: 요약만 성공으로 쓰기 차단 — 최종 상태는 게이트에서 유도, 자유기입 금지).
- V-3 예외 = 사전 승인 artifact{owner·근거·만료·적용 selector}만, receipt에 digest 결속. 실행 후 임의 추가 금지.

## 2. 반례 (구현 포함 — 75 §9의 OV-01~14 전부)

핵심: OV-01(테스트 0개 가림)·02(사후 변경+옛 인계)·03(재작성 digest)·04(캐시 dist 출처 불일치)·05(딴 서버 지정)·06(전부 skip)·07(-k 주입)·08(증거 짜깁기)·09(SHA 같음+suite 다름 재사용)·11(WARN 승격)·12(infra_error 요약 위조)·13(lab 소스 불일치)·14(잔존 볼륨). 각각 **거짓 verified를 실제로 차단**해야 함.

## 3. 재사용 지도 (75 §10)

| 자산 | 판단 |
|---|---|
| `pytest_runs.py`·`testruns.py` | **이관 재사용**(+env차단·nodeid 대조·retries=0 보강) |
| `result_io.py` | 부분 재사용(digest≠인증 명시) |
| candidate commit/tree lock·gitprim | 재사용 |
| test-agent | 제한 재사용(표시층 한정·WARN 불승격) |

## 7. v1 범위 밖 (후속 기록 — 구현 금지)

- **보호된 CI에서 receipt/artifact 발행·서명**(진위 보증 완전체) — GitLab 반영 후.
- **lab 정비**(지정 체크아웃=실행 이미지 일원화·초기화 정책) — 운영 작업, Codex가 필요 절차를 결과서에 제안만.
- UI mutation/negative control 자동화 고도화.
