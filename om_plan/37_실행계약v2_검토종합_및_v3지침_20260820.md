## Codex 단독 — 구현자만 아는 결정적 사실

1. **결속 모델이 이미 존재한다(재발명 금지):** `CandidateLock`(repo·commit·tree·artifact 결속, candidate.py), `TestRunSet`(candidate·artifact·harness·suite·필수test 결속, testruns.py), `ReleaseLock`(결과·후보·testrunset·policy·catalog·image, release.py). → v3의 verify-receipt는 **이걸 참조**해야지 필드 나열로 복제하면 안 됨. (E의 "재계산하라"를 구현으로 실현하는 실체)
2. **P0-5 A5 미해소 재확인:** apply 작업트리에 아직 current-재계산 미커밋 변경이 남음 → P1-1 원본기준 결정과 실제 코드가 다름. **v3 착수 전 A5 되돌리기 먼저.**
3. **resume 경계:** 기존 resume은 "구현 전 block + input-lock/facts 불변"만 허용. **구현 후 deviation은 반드시 새 run**(supersedes_run_id 등 결속). v2의 "새 run 또는 resume"은 이 경계를 흐림 = 우회 통로.
4. **Q9 과대해석:** Q9는 "plan approval exit2를 CI 성공 표시"만 확정. **"구현 자동 승인"은 확정 안 됨.** `automation-policy:<id>` 문자열 자기신고는 승인 증거 아님 → Q13 확정 전 자동 plan-approval 금지.
5. **proposal 무스키마:** 필수 파일명 오탈자(`contract-to-run`)·extra 파일을 못 잡음 → proposal index+digest 필요. plancore에 OM literal 넣지 말고 integration 주입.

## v3 필수 축 (E+Codex 합의) — 이걸 확정해야 구현 가능

1. **아티팩트별 canonical digest + self-digest 제외규칙 + 재계산 주체** 정의. plan-approval은 latest validation-attempt digest + plan-result digest에 결속.
2. **facts 모델에 ID별 관계 보존**: ID→product paths / ID→contracts→test selectors / shared path→owner IDs / 경로→{repo, change_type, digest}. product·checker repo namespace 분리 + checker candidate ref/diff 추가.
3. **subset 폐기 → 항목 완전성**: implement-result를 required/optional/retired/manual_action 항목 단위로. verify가 `git diff(base..impl)` 재계산해 observed와 완전일치 요구.
4. **verify-receipt = 기존 CandidateLock·TestRunSet·ReleaseLock 참조**(복제 금지) + apply가 digest 체인 재검산. partial verdict apply 금지 명문화.
5. **2차판독 out-of-band를 upgrade approval 하드 전제로**: CI가 별도 컨텍스트 기동·byte 대조. 로컬 단독은 review_pending까지만.
6. **resume/새 run 경계 명문화**: 구현 후 변경=새 run + supersede 결속. 완료 approval 재사용 차단.
7. **curated 수동변경 = action receipt + 새 run**: 승인 delta digest·수행자·결과 digest 결속.
8. **mutant 유의미성 하한 + Q7 범위 제한**: 파일삭제류 금지, 국소변조만. Q7 확정 전 필수화 보류(기존 patch-kill 범위 재사용).
9. **owner/자동승인은 Q13/Q6 후**: 그전까지 approved_by=사람만, owner=선언(신원검증 없음 명시).
