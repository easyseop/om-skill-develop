# 사용법 문서 보류 + CLI 단순화 결정 (2026-08-18)

## 결정 (사용자)

1. **README 사용법은 지금 넣지 않는다** — 현재 CLI가 복잡해 설명서도 복잡해짐.
   최종 형태(단순화된 명령 + 슬래시 명령 설치 후)가 나온 뒤 한 번에 올린다.
   검증까지 마친 초안은 아래에 보관.
2. **로컬 CLI를 단순화한다** — `plan-preflight --request … --run-dir … --state-root …
   --session-id …` 4개 인자는 운영 관리가 어렵다. 한 명령으로:
   run 폴더 자동 생성(새 run 규칙과 오히려 일치), state-root 기본값, session-id 자동.
   명시 옵션은 override로 유지, 안전 의미(마커·불변·재실행 규칙)는 불변.

## 검증된 운영 모델 (사용법 초안의 핵심 — 문서화는 보류, 사실은 기록)

- 파이프라인은 **web 수동 실행만** 허용, 시작 시 입력 5개:
  request-ref/path · proposal-ref/path · product-project
- **2단계 모델**: ① 로컬(비신뢰)에서 요청 작성→preflight→proposal 작성→자가 validate
  ② 요청+proposal을 MR로 커밋 후 파이프라인이 전 과정 재검증
  (guard → preflight 재수집 → intent-review 사람 승인(intent-summary.md 확인) →
  proposal 격리 패키징 → validate 재계산 대조)
- 판정은 green/red가 아니라 validate 결과 + review_state. approval = 검토 준비 완료.
- 이 모델은 .gitlab-ci.yml spec inputs·job 스크립트·승인 문구·스키마 실물 대조로 검증됨.
  (최초 초안은 "파이프라인 안에서 제안 생성"으로 잘못 기술 → 검사 과정에서 교정)
