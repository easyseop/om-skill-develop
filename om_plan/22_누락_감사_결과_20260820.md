## B. 내 문서(management-files.md) 정정 필요

B감사가 실증: **apply는 등록 파일 `source:` 블록·기존 entry의 status/owner_status/provenance를 전혀 안 바꾼다.**

- 내가 "[자동] 승인 시 갱신"이라 적은 것 중 **실제로 그렇게 동작·설계된 게 아닌 것**:
  - `status` proposed→active: 등록엔 "proposed" 상태가 없음. 제안은 proposal/에만. 신규 entry는 바로 active 하드코딩(`registration_prep.py:200,229`). **전이 개념 자체가 없음.**
  - `provenance`: source-snapshot(최초)/candidate-follow-up(신규)만. change/upgrade 후에도 **영구 불변**(policy `:183-185`). 갱신값·전이 설계에 없음.
  - `owner_status`: apply 자동 전이 안 함(사람 배정, Q4=B와 일치).
  - `source.snapshot_sha`·`upstream_*`·`changed_path_count`: apply 불변.
- → management-files.md의 [자동] 분류를 **"apply가 실제로 갱신하는 것"과 "설계에 전이 없음(=미규정 갭)"으로 재작성**해야 함. 필드 생애주기표는 애초에 설계에도 없었으므로(B감사 Q2) 우리 문서화가 최초이자, 그래서 실제 코드에 맞춰야 함.
