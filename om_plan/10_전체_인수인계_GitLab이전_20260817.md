# 0. 한 장 요약

- **`/om-plan`은 "계획 세우기" 명령이고, 코드는 만들어졌으며 적대적 검토를 통과했다.**
- 3단계 설계 중 첫 번째다: **`/om-plan`(완료) → `/om-implement`(미착수) → `/om-verify`(미착수)**.
- 지금은 **GitHub→GitLab 이전 중**이다. 코드·CI 배선·1.13.1 제품 콘텐츠 확보까지 끝났고,
  남은 건 **GitLab에 올리기 + GitLab 외부 설정 + 실제 1회 실행**이다.
- **코드 검토 통과 ≠ 운영 완료.** 실제 GitLab 파이프라인은 아직 한 번도 안 돌렸다.

# 1. `/om-plan`이 무엇인가

OpenMetadata에 은행 커스터마이징(BANK-OM-001~007)을 얹은 코드를 버전업할 때, "커스터마이징이
살아남았나"를 **계획 단계에서** 검사하고 근거를 남기는 슬래시 명령. 역할 3분할이 뼈대다.

- **LLM** = 조사·계획 제안만(전부 `proposed` 라벨). `observed`(기계 사실)를 만들 수 없다.
- **검사기(Python·Schema)** = Git 사실 수집·형식 검증·지문(digest) 결속. LLM을 신뢰하지 않는다.
- **사람** = 업무 의미·위험·승인(STOP 지점에서만).

핵심 상품 한 줄: **"LLM이 잘한다" → "LLM이 틀려도 걸린다"**.

모드 4종: initial(최초등록)·feature(신규기능)·change(기존수정, pre_plan/post_change_reconcile)·
upgrade(버전업). `/om-plan`은 소스(git 커밋·파일)만 읽는다 — 서버를 띄우지 않는다.

# 3. 계속 보류된 결정 (Claude·코덱스 임의 확정 금지)

이 5개는 **코드로 정하면 안 되고 사람(사용자·조직)이 정하는 결정**이다. 첫 인수인계서
CLAUDE.md 규약: "사람 결정 항목(Q1~Q9 류)은 Claude도 코덱스도 임의 확정하지 않는다." 검토
결과마다 "임의 확정하지 않았다"고 명시하는 이유가 이것 — 사용자 재촉이 아니라 "몰래 정하지
않았다"는 표시다.

| # | 무엇을 정하는가 | 언제 필요해지나 | GitLab 이전에 필요? |
|---|---|---|---|
| **Q3** | 공용 코드 정의를 delta로 둘지 값 기반 pointer로 전환할지 | 등록자료 템플릿·clean export 설계 때 | ❌ 아님 |
| **Q6** | 승인자 신원을 조직 인증과 어떻게 연결할지 | 운영 도입 때 | ❌ 아님(단 GitLab 승인자 설정과 개념상 관련) |
| **Q7** | patch-kill(일부러 코드 빼서 검증)의 범위·복구·비용 | `/om-verify` 설계 때 | ❌ 아님 |
| **Q8** | 병합 conflict-rate 자동 산정 기준 | 병합 위험 검사 설계 때 | ❌ 아님 |
| **Q9** | `approval`(exit 2)를 CI 성공으로 처리할지 | **GitLab 실제 pipeline 돌릴 때** | ⚠️ 실행 단계에서 |

**요지:** Q3·Q6·Q7·Q8은 훨씬 나중 단계라 **GitLab 이전과 무관**하다. **Q9만** 실제 GitLab
pipeline을 돌리는 단계에서 "정상 계획인데 exit 2라 빨간불로 뜨는 것을 성공으로 볼지"를
정해야 한다. **모두 지금(이전 준비) 단계에서는 정할 필요 없고, 코덱스에게 추가로 시킬 일도
없다.** "나중 숙제"로 표시만 유지한다. 다음 세션도 이 5개를 임의로 채우지 말 것.

# 4. 작업 경위 (문제→결정 요약, 시간순)

각 단계의 상세 근거는 §8의 바탕화면 파일에 있다.

1. **3차 적대적 구현 검토** (`3차검토결과_20260814`) — 1차 구현(commit `a564d48`)을 mutation·
   PoC로 검토. 재계산 탐지·self-digest·owner 비위조 등이 실재함을 입증. **P1-A 발견**: validate가
   run-request.refs를 재고정 안 해, input-lock+facts를 다른 커밋으로 일관 재작성하면 approval.
2. **P1-A 설계 재검토** (`P1-A_설계재검토`) — run-request까지 3파일 재작성하면 지문이 합법
   계획과 **완전 동일**함을 실증(구별 불가). 결론: run 내부 대조로는 불가, **신뢰 루트를
   run 밖(사람/CI가 전달하는 expected digest)에 둬야**. 권고 = E안(외부 expected digest).
3. **E안 최종 판단** (`E안_최종판단`) — Codex의 E 정리를 검토. upgrade 문서가 input-lock에
   결속 안 되던 것(불충분) 등 지적. verdict enum은 공유 자원이라 바꾸지 말 것.
4. **E-hardening 구현 검토** (`E안_구현재검토`, commit `1f02e1d3`) — expected digest 게이트,
   빈 proposal block, no_change 규칙, review_state, 문서 결속까지 구현. **주장 10개 참, P0/P1
   없음 → 채택.** 신규 결함 3건은 사람 검토 경계 내 P2.
5. **보호 CI 배선(GitHub)** (`CI배선_적대검토`, commit `9bc4cd2c`) — GitHub Actions로 preflight→
   intent-review→proposal→validate. 격리 견고. **발견: catalog 지문에 `.pyc`가 섞여 cross-runner
   analysis_error(P2-1, fail-closed).**
6. **.pyc 수정** (`pyc수정_재검토`, commit `7aaa18f`) — `directory_digest`에서 `__pycache__`/
   `.pyc`/`.pyo` 제외. 캐시 억제 없이 통과 + `.py` 위조는 여전히 차단. **채택.**
7. **GitHub 폐기 → GitLab 전환** — 사용자 결정. GitHub 배선은 참조용 보존, GitLab로 재배선.
8. **GitLab 보호 CI 배선** (`GitLab배선_적대검토`, commit `ee9f033`) — 5개 신뢰 성질을 GitLab
   기능(protected environment 승인·protected runner·`GIT_STRATEGY:clone`·`prepare_trusted_checker.sh`)
   으로 재구성. all-skipped-green 없음(reject job이 명시 실패). `.pyc` 통로도 cleanup+
   `PYTHONDONTWRITEBYTECODE`로 닫음(실증). **P0/P1 없음 → 채택(외부 설정·실 pipeline 조건부).**
9. **제품 clone blob 확보 수정** (`제품clone수정_재검토`, commit `ef48a8e`) — GitLab CI가 제품을
   `--filter=blob:none`(내용 제외)으로 받아 검사기의 fail-closed와 충돌하던 것을, 제품 clone
   2곳에서 filter 제거(full clone)로 해소. **채택.** 잔여 P2: fail-closed의 `GIT_NO_LAZY_FETCH`가
   Apple Git 2.39에서 무시됨(실증) — full-clone이라 발현 안 되나 실 runner 미검증.

# 7. 미결·주의(P2, 비차단) 및 환경

- **P2 no_change 근거 관련성 미검증** — 무관한 실재 fact로도 review_ready 통과(사람 검토 범위).
  강화안: 무변경 입증 fact(changed-paths 빈 값)로 evidence 한정.
- **P2 `.pyc`/promisor 방어심화** — 제품 clone이 promisor 없음(full)을 코드로 단언 권장. 실
  GitLab runner의 git이 `GIT_NO_LAZY_FETCH`를 존중하는지 미검증(Apple Git 2.39는 무시 — 실증).
- **P2 full clone 비용** — 제품(2.7GB)을 run당 2회 clone. 필요 시 `--no-checkout`·범위 최적화.
- **환경:** 이 Mac git = Apple Git 2.39.3. `/private/tmp/*`는 재부팅 시 사라짐(임시). 검토는
  지정 커밋을 `git archive`로 추출해 읽기 전용 수행(원본 무변경).
