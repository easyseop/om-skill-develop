# 스킬 공장으로 만든 md 3종 — 실전 8일간 수정 0회

## 핵심 수치

| | 값 |
|---|---|
| 대상 | om-plan · om-apply · om-verify SKILL.md 3종 |
| 만든 방법 | 스킬 공장(claude-skill-author): 규칙 89개 전수 검사 + 모든 문장에 코드 실측 근거 + 독립 감사 |
| 출고 전 저작 단계에서 잡아 고친 결함 | 7건 (전부 출고 전 소진) |
| 실전 부하 (8/26~9/2) | 계획 run 10+회 · 반영 재주행 4회 · 검증 2회 · 핫픽스 4회 |
| **실전 8일간 스킬 md 수정** | **0회** |

git 이력 실측: `.claude/skills/`가 변경된 커밋은 이식 시점(8/24~25)뿐. 실전 기동(8/26) 이후 스킬 md는 한 글자도 바뀌지 않았다. 핫픽스 4회는 전부 엔진 코드·계약 테스트였고 스킬 md는 0건.

## 의미

스킬 md 0회는 초안이 완벽했다는 뜻이 아니다 — 초안은 저작 단계에서 결함 7건을 잡아 고쳤다. **"저작 시 검증 비용을 치르면 운영 수정 비용이 0이 된다"**가 결론이다.

## 참고 (직접 비교 아님)

같은 기간 손으로 쓴 문서(가이드 94A·요청서 템플릿·지시서)는 6회 이상 수정됐다(JDK 버전 오기·antlr4 누락·장부 커밋 단계 누락·필드명 오류 등, 전부 실전 정지 후 발견). 단 문서 종류가 달라(명령 정의 vs 운영 안내) 스킬 md와 직접 비교는 아니며, "검증 공정 유무"의 방향성만 참고한다. → 손문서도 실측 근거를 강제하는 방향으로 옮기는 것이 과제(백로그).
