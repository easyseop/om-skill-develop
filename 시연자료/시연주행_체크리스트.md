# 시연용 재주행 체크리스트 (새 브랜치, 완주 후 실행)

> 사용자 방침(2026-08-28): "지금(실전 주행)은 유심히 안 보지만, 다시 처음부터 돌릴 때는 꼭 시연자료를 고려해야 한다."
> 전제: 실전 완주 후 → 코덱스 개선 라운드(백로그 P1) 반영 → 새 브랜치에서 재주행하며 아래를 단계마다 원문 그대로 채집.

## 채집 원칙 (기존 규약 그대로)
- 원문 그대로(재해석 금지) · 유형별(성공/차단/발견/기준정보) · **작업단계별 계층**
- 각 장면마다: 입력한 명령(사람이 친 것) / 검사기 원문 출력 / 화면 확인 지점

## 단계별 채집 지점
1. **준비**: 새 브랜치 생성 명령·기준 커밋, 요청서 원문, 봉인값 발급 장면(input_lock_digest를 사람이 받아 적는 장면)
2. **/om-plan**: plan start→check 흐름, exit 2 승인 화면 원문, plan_digest 발급, (가능하면) 의도적 오류 1건으로 block 장면 재현 — "게이트가 실제로 막는다" 증명용
3. **사람 승인**: 결정 요청 표준형식(3줄 요약+선택지+권고) 실물, 승인 입력 문장
4. **/om-apply**: 단위별 커밋 로그, 이식 장면(줄 단위 diff 스크린샷 후보: SVG 4줄·48줄 3분해·case→맵), **승인 창구 장면**(awaiting→승인 기록→같은 SHA 재검사→pass — S10 재현), 게이트 8/8 표
5. **/om-verify**: 툴체인 확인, build receipt, 컨테이너 기동, 계약 9종 실행 원문, verified 판정
6. **황금 diff**: 최종 114경로 diff 확인 명령과 출력(재현성 증명 — 실전 주행과 동일함을 대조)
7. **마무리**: 대시보드·원문기록집 아티팩트 갱신, 하네스_원칙_실증 12조와 장면 매핑

## 실전 주행과의 차별점 (시연에서만 추가)
- 각 장면 직후 스크린샷/터미널 원문 즉시 저장(나중에 소급 수집 금지)
- 사람이 친 입력은 "슬래시+할동작+자연어"만 나오게 (UX 원칙 실증)
- 차단 장면 1건 이상 의도 재현 (성공만 있으면 게이트 증명이 안 됨)
