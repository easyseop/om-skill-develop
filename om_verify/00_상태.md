# /om-verify — 상태: 인터페이스 후보 (미설계)

- 역할 후보 3종: `changes`(계획 vs 실제 Git 변경) · `contracts`(기능별 동작 시험) · `candidate`(코드·테스트·이미지 대상 일치).
- 확정 시점: 각각 00 로드맵의 조건 충족 후.
- 미리 넘겨받은 결정·논의:
  - patch-kill(허위 테스트 방지)의 재설계는 이 단계에서 검토 — 실행 환경·복구·비용 포함 (Q7 권고 B)
  - conflict-rate 자동 측정(격리 시험 병합) 여부는 Q8 — 이 단계의 changes/candidate와 연동될 수 있음
  - "테스트 개수·전부 green"을 신뢰 신호로 쓰지 않는다는 규칙은 여기서도 유지 (phase WIP 교훈)
- 설계 시작 시 이 폴더에 문제별 기록을 쌓는다.
