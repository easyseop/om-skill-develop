# 주간보고 — OpenMetadata 커스터마이징 자동화 프로세스 구축 현황

작성일: 2026-09-02 (이전 버전: `주간보고_프로세스구축_현황_20260821.md` — 히스토리 보존)

> **이번 주 핵심 한 줄**: 1.13.1 → 1.13.2 실제 업그레이드를 **계획 → 반영 → 검증 한 사이클 전부 자동으로 완주**했다. 필수 계약 테스트 9종 전부 통과(verified). 사람은 슬래시 명령과 승인만 했다.

## 0. 이 프로젝트란 (한눈에)

**은행이 OpenMetadata에 넣은 개조(커스터마이징)를 "기능 단위 고유 ID"로 등록·관리하고, 그 ID를 기준으로 등록·수정·버전업·검증을 일관되게 운영하는 프로세스를 만든다.**

- 각 개조를 고유 ID(예: `BANK-OM-001`)로 등록하고, 그 ID에 바뀐 파일·지켜야 할 동작·필수 테스트를 묶어 관리한다.
- 이 ID 기준 관리를 사람 손이 아니라 **LLM(제안) + 규칙(검증) 자동화 파이프라인**으로 운영한다. 사람은 위험·예외·최종 통합만 검토한다.

## 2. 무엇을 만들고 있나 (목표 — 불변)

OpenMetadata에 은행 커스터마이징을 등록·수정·버전업할 때, LLM이 변경을 계획·반영·검증하고 규칙(결정론 검사)이 매 단계를 강제하며, 사람은 위험·예외·최종 통합만 검토하는 자동화 파이프라인.

핵심 원칙:
- **LLM은 제안하고, 규칙(검사기)이 검증한다.** 검사기는 LLM을 안 타므로 속일 수 없다.
- 각 단계는 앞 단계 산출을 근거로만 진행한다.
- 문제가 있으면 다음 단계로 안 가고 앞 단계로 되돌린다.

## 3. 실현 = 4 커맨드 + 사람

### ① /om-plan — 사전 분석  ✅ 완성 · 실전 검증
- 변경 "계획"을 LLM이 쓰고 규칙이 검증. 아무것도 실제로 바꾸지 않음.
- 모드 4종(initial·feature·change·upgrade) 전부 동작. 이번 업그레이드에서 upgrade 모드를 실전 사용.
- **실전 실적**: 계획 run 10회+ 수행, 매번 검사기 판정(exit 0/1/2/3)을 재해석 없이 따름. 계획 결함 다수를 apply 이전에 적발·정정.

### ② /om-apply — 커스터마이징 반영  ✅ 완성 · 실전 완주
- 확인된 계획만 코드에 반영하고 각 변경에 커스텀 ID를 commit에 남긴다.
- **실전 실적**: 8단위(백엔드·스펙·생성TS·UI·언어팩·아이콘·유틸분해·유틸이관) 커밋, 관리 파일 10개 갱신, 3방향 정합 검사 통과. 언어팩 646키 유실 0, 이식 3건 무결. **같은 작업 4회 재실행에서 결과 완전 동일**(재현성 입증).

### ③ /om-verify — 변경·기능 검증  ✅ 완성 · verified
- 계획↔실제 변경 일치, 필수 테스트 실행·통과, 최종 코드/이미지 결속을 확인.
- **실전 실적**: 후보를 실제 이미지로 빌드 → 격리 환경 기동 → **계약 테스트 9종 전부 통과**(API 4·브라우저 3·정적 2), skip·error 0. 실제 브라우저로 은행 화면(확장 컬럼·실패 단언·한글 입력)까지 확인.

### ④ /om-report — 결과 요약  ⬜ 미착수
- A~D의 통과·중단 사유·다음 행동을 한 화면에. 아직 커맨드 없음.

### ⑤ 사람 검토
- 담당자가 결과를 보고 다음 작업을 선택. 이번 사이클 내내 사람은 슬래시 명령 + 승인 결정만 수행.

## 4. 이번 사이클에서 발견·수정한 것

실전 첫 완주 과정에서 나온 것을 유형별로 정리(상세: `시연자료/수정핫픽스_전체정리.md` · 대시보드 아티팩트):

- **검사기 핫픽스 4건** — 훅 실행 순서 / 공유 경로 사람 승인 입력 / apply·verify 시작조건 충돌 / 계약 실행 규약 2건. **전부 검사기 파이썬 코드·스키마 수정**(SKILL.md 지침은 0회 수정), 반례 테스트 동반, MR merge 완료.
- **환경·빌드 함정 5건** — JDK 21·antlr4·디스크·서버 사양 등. 이 서버 첫 빌드의 1회성 통과의례. `시연자료/기준정보/D6` 체크리스트로 정리.
- **계획·문서 정정 6건** — 계획서 정합·참조 rename·가이드 오류. 검사기가 배포 전에 적발.
- **제품 코드 결함: 0건.** 최종 통과 시 제품 트리가 직전과 동일 — 통과 원인은 코드 수정이 아니라 검사 방식 교정이었음.

> 관통 통찰: 순수 코딩 실수는 1건뿐. 나머지는 전부 **단계와 단계가 만나는 경계**의 규약 누락/불일치였고, 모두 기계 게이트가 먼저 잡았다.
