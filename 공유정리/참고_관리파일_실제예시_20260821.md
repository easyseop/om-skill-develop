# [참고] om-plan 핵심 관리파일 — 실제 예시 (1.13.1)

> om-plan이 등록·관리하는 핵심 관리파일들의 **실제 예시 하나씩**입니다. 각 파일이 무슨 역할인지 감을 잡는 용도. (실제 1.13.1 등록자료에서 발췌)

## 1. customization-registry.yaml — 전체 등록 명단
"어떤 버전 기준으로, 어떤 커스텀들이 등록돼 있나"의 최상위 목록. `source`(기준 버전 정보) + `entries`(커스텀별 항목).

```yaml
schema_version: 1
source:
  repository: easyseop/OM_TEMP
  snapshot_sha: d952a838...            # 커스텀 코드 기준 커밋
  upstream_repository: open-metadata/OpenMetadata
  upstream_tag: 1.13.1-release          # 공식 기준 버전
  upstream_sha: afcb2d2c...
  changed_path_count: 111               # 원본 대비 바뀐 파일 수(변경 전 릴리즈 기준)
  ancestry_preserved: true
  diff_inventory: source-diff-paths.txt
  unregistered_findings: []             # 등록 안 된 변경(누락). 지금은 없음
  shared_code_definitions: shared-code-definitions.yaml
entries:
- customization_id: BANK-OM-001         # 커스텀 고유 ID
  title: 기준코드(InstanceCode)
  owner: 데이터시스템부                  # 담당자
  owner_status: assigned
  status: active
  criticality: high
  manifest: manifests/BANK-OM-001.yaml  # 이 커스텀의 상세 명세
  contracts:                            # 이 커스텀이 지켜야 할 계약
  - CONTRACT-INSTANCE-CODE
  provenance: source-snapshot
```

## 2. manifests/BANK-OM-XXX.yaml — 커스텀 하나의 상세 명세
그 커스텀이 **어떤 파일을 바꾸는지**, **꼭 바뀌어야 할 파일**, 지켜야 할 계약 등. (예: 작은 것 BANK-OM-005 전문)

```yaml
schema_version: 2
customization_id: BANK-OM-005
status: active
kind: core-patch
title: 한글 입력 조합 보정
implementation:
  changed_paths:                        # 이 커스텀이 바꾸는 파일 목록
  - openmetadata-ui/.../SchemaEditor/SchemaEditor.test.tsx
  - openmetadata-ui/.../SchemaEditor/SchemaEditor.tsx
  required_changed_paths:               # 그중 반드시 바뀌어야 하는 핵심(load-bearing)
  - openmetadata-ui/.../SchemaEditor/SchemaEditor.tsx
upgrade_watch:
  paths: [ ... ]                        # 버전업 시 주시할 경로
assurance:
  contracts:                            # 이 커스텀의 계약
  - CONTRACT-KOREAN-IME
  direct_tests: []                      # (폐기된 통로 — 지금은 계약을 통해서만)
series:
  allowed: true
  depends_on: []
```

## 3. contracts.yaml — 업무 정상 조건(계약)
커스텀이 **지켜야 할 동작(불변식)** 과 그것을 확인하는 **필수 테스트**. (예: 계약 1개)

```yaml
id: CONTRACT-INSTANCE-CODE
title: InstanceCode CRUD, search, and index round-trip
invariant: InstanceCode의 codeGroup/codeValue가 CRUD와 재색인 뒤에도 동일하게 조회된다.
required_tests:
- tests/bank/contracts/test_instance_code.py::test_crud_search_roundtrip
customization_ids:
- BANK-OM-001
```

## 4. shared-path-owners.yaml — 공유 파일 소유 지분
여러 커스텀이 **함께 건드리는 파일**과 그 소유 ID들. (한 파일을 여러 커스텀이 나눠 씀)

```yaml
bootstrap/sql/migrations/native/1.13.1/mysql/schemaChanges.sql:
- BANK-OM-001
- BANK-OM-002
openmetadata-service/src/main/java/org/openmetadata/service/Entity.java:
- BANK-OM-001
```

## 5. shared-code-definitions.yaml — 공유 코드 정의(내용 앵커)
공유 파일에서 **각 커스텀이 넣은 실제 코드 조각**을 지문처럼 고정. 버전업 때 이 조각이 살아있는지 확인.

```yaml
schema_version: 1
definitions:
- path: bootstrap/sql/migrations/native/1.13.1/mysql/schemaChanges.sql
  customization_id: BANK-OM-001
  assertions:
  - id: bank-om-001-schemachanges-1
    matcher: code_fragment
    fragment: |
      -- InstanceCode entity table ...
      CREATE TABLE IF NOT EXISTS instance_code_entity ( ... );
```

## 6. repository-layout.yaml — 경로 규칙·공식 소유 영역
경로 문법(symlink/submodule 거부 등)과 **공식이 소유한 루트**(커스텀이 함부로 못 건드리는 영역).

```yaml
schema_version: 1
upstream_base_sha: afcb2d2c...
path_grammar:
  name: gitignore-pathspec
  symlink_policy: reject
  submodule_policy: reject
  lfs_policy: reject
upstream_owned_roots:
- openmetadata-service/**
- openmetadata-spec/**
- openmetadata-ui/**
```

---

## 한눈에 — 파일들이 어떻게 엮이나

- **registry**(명단) → 각 항목이 **manifest**(상세)와 **contracts**(계약)를 가리킴
- 여러 커스텀이 겹치는 파일 → **shared-path-owners**(누가) + **shared-code-definitions**(무슨 코드)
- 전체 경로 규칙·공식 영역 → **repository-layout**
- 이 파일들이 **항상 실제 코드와 일치**하도록 유지하는 게 om-apply의 핵심(관리파일 싱크).
